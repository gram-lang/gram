Once a recipe has been parsed by `@gram-lang/parser`, scheduled by `@gram-lang/kitchen`, and enriched by `@gram-lang/analyzer`, it is ready for visual presentation.

The `@gram-lang/renderer` package consumes this complete JSON object and formats it into structured Markdown or semantic HTML markup.

## Output formats

The renderer supports five primary export targets:

### 1. Markdown (`toMarkdown`)
Generates standardized GitHub Flavored Markdown (GFM) containing a formatted shopping list, equipment inventory, numbered instructions, footnotes (`[^1]`), gross purchasing mass badges, and an optional nutritional panel (`## 🥗 Nutrition`). This format integrates cleanly with static site generators (Astro, VitePress, Hugo) and personal knowledge management tools (Obsidian).

### 2. Semantic HTML (`toHTML`)
Produces clean, semantic HTML markup. The HTML formatter employs an **inversion of control** architecture, allowing you to inject custom CSS classes (e.g. Tailwind CSS) and SVG icon sets to match your host application's design system.

### 3. Print-ready HTML (`toPrintHTML`)
Generates a complete, self-contained `<!DOCTYPE html>` document featuring an inlined print stylesheet (A4 format, page-break-aware sections) and standalone vector icons. Designed for direct browser printing without external stylesheet or asset dependencies. While custom classes cannot be injected into `toPrintHTML`, formatting helpers (`formatDuration`, `formatFraction`, `hideStepQty`) remain fully supported.

### 4. Interactive Gantt chart (`toGanttHTML` + `attachGanttInteractivity`)
Renders an interactive timeline visualizing active steps, passive background timers, and masked-time compression as an HTML fragment. Integration uses a two-phase architecture: `toGanttHTML` generates static markup, while `attachGanttInteractivity(container, options)` attaches hover tooltips, time-mode toggles, and client-side controls via DOM event delegation. See the [renderer API reference](/docs/reference/api/renderer) for complete `GanttRenderOptions` and `GanttInteractivityOptions` specifications.

The `miseEnPlace` option (`"perSection"` by default, `"upfront"`, or `"perSession"`) controls preparation placement, while the `rests` option (`"shortest"` by default, `"balanced"`, or `"longest"`) determines the duration of passive timers defined as ranges: the chart plots the timeline computed from the recipe's task graph for that configuration (see [Scheduling the mise en place](/docs/explanation/alap-scheduling#scheduling-the-mise-en-place)). Section preparations are rendered as dashed blocks styled with section-specific accent colors (D-1, Day D). These options also govern total and idle durations displayed in HTML, Markdown, and print document headers.

The Gantt chart can also project recipes onto the real calendar via the `projection` option (supplied by `project()` from `@gram-lang/scheduler`). The chart renders scheduled plan blocks (adjusted passive durations are highlighted with distinctive borders and notes), calibrates its time axis to local wall-clock time, and shades user unavailability periods. See [Planning in real time](/docs/explanation/planning-in-real-time/).

### 5. Production run sheet (`runSheetToText`, `runSheetToMarkdown`, `runSheetToHTML`, `runSheetToPrintHTML`) <Since v="1.4.0" />
Formats the projected schedule generated by `project()` into an operational kitchen roadmap: daily session breakdown relative to service (D-1, Day D), chronological task sequencing with timestamps rounded to the nearest five minutes, annotations for adjusted passive durations, and unresolved constraints. Labels adhere to the configured `lang` option. The `describeRunSheet()` helper outputs this same run sheet as structured data, facilitating exports to third-party formats (such as the CLI's iCalendar export).

## Unified traversal (`RenderBackend`)

Internally, document formatters (Markdown, HTML, Print HTML) delegate content iteration to a central orchestrator (`renderRecipe` in `traversal.ts`), which interfaces with each format's `RenderBackend` implementation. This architecture guarantees strict structural parity: titles, metadata, ingredient lists, cookware, instructions, footnotes, and nutritional breakdowns are traversed in the exact same sequence across all output targets. The Gantt chart operates independently of this traversal, as it models a chronological timeline graph rather than a sequential text document.

## Usage example

```typescript
import { toMarkdown, toHTML } from '@gram-lang/renderer';

// Assuming `recipe` originates from @gram-lang/kitchen or @gram-lang/analyzer
const recipe = {
  title: "Simple Crepes",
  metrics: { preparationTime: 5, activeTime: 10 },
  // Reference schedule consumed by the renderer
  schedule: {
    miseEnPlace: "perSection",
    rests: "shortest",
    totalTime: 30,
    idleTime: 15,
    blocks: [],
    sessions: [],
  },
  shopping_list: [
    { id: "flour", qty: 200, unit: "g" }
  ],
  sections: [
    {
      title: "Preparation",
      steps: [
        { type: "text", value: "Whisk everything together." }
      ]
    }
  ]
};

// 1. Standard Markdown rendering
const markdown = toMarkdown(recipe);

// 2. Customized HTML rendering (Inversion of Control)
const html = toHTML(recipe, {
  icons: {
    clock: '<svg class="icon-clock">...</svg>',
    fire: '<svg class="icon-fire">...</svg>'
  },
  classes: {
    recipeTitle: "text-2xl font-bold custom-title",
    recipeMeta: "flex gap-2 text-gray-500"
  }
});
```

The `RendererOptions` interface also provides `bakersReference`/`bakersMathOnly` (baker's percentages), `hideStepQty` (hiding in-step ingredient quantities), and `renderId`. The latter prefixes anchor identifiers (e.g. `"note-1"`) to prevent HTML ID collisions when multiple recipes share a single web page.

## Cross-cutting features

- **Fraction formatting**: Formats floating-point values into readable vulgar fractions (`0.5` → `"1/2"`, `0.33` → `"1/3"`). Output consists of clean ASCII character sequences (`1/2`), avoiding single-glyph Unicode fractions.
- **Escaping and security**: All user-provided strings are sanitized. Output produced by `toHTML` and `toPrintHTML` is safe for direct DOM insertion. The `toMarkdown` formatter explicitly escapes `<` and `&` (converting them to `&lt;` and `&amp;`), preventing malicious HTML execution during downstream markdown parsing.
  :::caution[Untrusted Content Security]
  While tag injection is prevented, `toMarkdown` does not evaluate URL protocols (e.g. `javascript:` links). When rendering untrusted third-party recipes, apply a dedicated HTML sanitizer (`DOMPurify` or `rehype-sanitize`) on the final markup.
  :::
- **Duration formatting**: Converts raw minute integers into natural duration strings (`90` → `1h 30m`).
- **Bundled CSS**: The package distributes `gram.css` (light/dark tokens for all components) and `gantt.css` for timeline layouts. Print documents embed these rules directly in the document `<head>`, requiring no external asset fetching.

## Direct JSON consumption

If you are developing a modern frontend application (React, Vue, Svelte, mobile), relying on `@gram-lang/renderer` is entirely optional.

The JSON emitted by `@gram-lang/analyzer` is strongly typed and directly iterable: looping over `recipe.sections` and `recipe.shopping_list` meets most UI requirements. For sophisticated edge cases (alternative ingredient groups, composites, baker's percentages, or `purchasingMass`), the internal implementation of `@gram-lang/renderer` serves as an established reference pattern.
