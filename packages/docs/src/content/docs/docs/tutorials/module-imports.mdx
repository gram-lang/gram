In [Your First Recipe](/docs/tutorials/first-recipe), a complete **Lemon Meringue Tart** was written in a single `.gram` file, including its own sweet pastry dough. That dough isn't specific to lemon tarts, though — the same base works under a chocolate ganache, a fruit clafoutis, or a dozen other fillings. Copy-pasting it into every recipe that needs it means fixing the same bug (or improving the same recipe) in a dozen places.

This tutorial pulls that dough out into its own file and pulls it back in with `@use` — Gram's module system.

## Step 1: Extract the base into its own file

Start from the dough section written in the first tutorial:

```gram title="Code"
## Sweet Pastry Dough ->&pastry dough{}

[Process] In a #food processor{}, the @flour{180g}, @icing sugar{55g}, and @salt{1/4 tsp}.

[Crumble] Add the @butter{115g}(cold, cut into small cubes) and mix for ~{1-2min} until sandy.

[Combine] Add the @egg{1}, @?vanilla extract{1/2 tsp} and mix until the dough comes together.

[Rest] Wrap in plastic and let it rest in the fridge for ~_{1h}.
```

Move it into its own file, `bases/sweet-pastry-dough.gram`. Two changes come with the move:

*   The `->&pastry dough{}` on the section title can go — it was there so the *host* recipe could reference the dough by name within the same file. A module's exports are determined by its sections instead (see [What a module exports](/docs/reference/syntax/modules#what-a-module-exports)), so a plain `## Sweet Pastry Dough` heading is enough for an importer to reach it.
*   A `yields:` key states how much dough this file actually produces, so any recipe that imports it can ask for a specific amount and have Gram scale the whole file to match.

```gram title="bases/sweet-pastry-dough.gram"
---
title: 'Sweet Pastry Dough'
yields: 450g
---

## Sweet Pastry Dough

[Process] In a #food processor{}, the @flour{180g}, @icing sugar{55g}, and @salt{1/4 tsp}.

[Crumble] Add the @butter{115g}(cold, cut into small cubes) and mix for ~{1-2min} until sandy.

[Combine] Add the @egg{1}, @?vanilla extract{1/2 tsp} and mix until the dough comes together.

[Rest] Wrap in plastic and let it rest in the fridge for ~_{1h}.
```

:::tip
`450g` is a rough total of the dough's own ingredients — no need to weigh it exactly. Without a declared `yields:`, Gram measures the module's own mass automatically instead; declaring it is just more precise, and slightly cheaper to compile (see [Scaling](/docs/reference/syntax/modules#scaling)).
:::

## Step 2: Import it from the tart

Back in the tart recipe, replace the dough section with an `@use` directive. Directives go right after the frontmatter, before the first step:

```gram title="lemon-tart.gram"
---
title: Lemon Meringue Tart
portions: 8
---

@use "./bases/sweet-pastry-dough.gram" as &dough

## Lemon Curd ->&curd

[Whisk] In a #saucepan{}, the @lemon zest{1 tbsp}<@lemon, @lemon juice{120g}<@lemon{2}, @sugar{125% @&lemon juice}, and @eggs{3}.

[Cook] Over ^{medium heat} for ~{8min} until thickened.

## Baking the Tart Shell ->&baked shell{}

[Preheat] The #oven to ^{350F}.

[Roll out] The &dough{450g} for ~{5min} and place it in a #tart ring{}.

[Bake] For ~_{20min} until golden. Let cool.

## Assembly

[Pour] The &curd into the &baked shell{}. Chill in the fridge for ~_{2h}.
```

Two things changed in the body, and nothing else did:

*   `&pastry dough{}` (an in-file intermediate reference) became `&dough{450g}` (an imported binding, requested by an explicit quantity).
*   Everything downstream — the Gantt timeline, the shopping list — is unaffected. The dough's own `~_{1h}` rest still interleaves with making the curd exactly as before, because `@use` inlines the imported steps into the same schedule rather than treating them as an opaque black box.

Requesting `&dough{450g}` against a module that yields exactly `450g` gives a scale factor of 1 — this tart uses the whole batch. Ask for less (`&dough{250g}` for a smaller tart shell) and Gram scales every quantity inside `bases/sweet-pastry-dough.gram` down to match, automatically.

## Step 3: Reuse it somewhere else

This is the payoff. A second recipe — a batch of jam tartlets, say — can pull in the exact same file:

```gram title="jam-tartlets.gram"
---
title: Jam Tartlets
---

@use "./bases/sweet-pastry-dough.gram" as &dough

## Tartlets

[Divide] The &dough{450g} into 12 small tart tins.

[Bake] At ^{180C} for ~_{15min} until golden.

[Fill] Each shell with a spoonful of @jam{15g}.
```

Fix a step in `bases/sweet-pastry-dough.gram` — the oven temperature, an ingredient quantity, a missing prep note — and both recipes pick up the change the next time they're compiled. Nothing to keep in sync by hand.

## Encapsulation, briefly

A module's own relative quantities and ingredient math (`@sugar{125% @&lemon juice}` in the curd, for instance) resolve only against *that module's own sections* — a host recipe that happens to use the same ingredient name for something else entirely never leaks into a base's math, and vice versa. This is the same section-scoping rule Gram already applies within a single file; splitting a recipe across files doesn't change it. See [Encapsulation](/docs/reference/syntax/modules#encapsulation) for the details.

:::note
This tutorial covers the everyday path: a relative import, a default binding, automatic scaling. For destructured bindings (`as { &a, &b }`), project-root and aliased paths (`@/`, `@alias/`), and the opaque `prepared` mode, see the full [Module Imports](/docs/reference/syntax/modules) reference.
:::
