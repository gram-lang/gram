Gram works in any editor that speaks the Language Server Protocol. VS Code has a dedicated extension; every other editor below runs the same [language server](/docs/reference/tooling/language-server/) from a few lines of configuration, given here as they are tested.

## What each editor gets

| Editor | Highlighting | Diagnostics | Completion | Hover | Formatting | Rename | Preview |
|---|---|---|---|---|---|---|---|
| [VS Code and its forks](#vs-code-and-its-forks) | Full (TextMate grammar and semantic tokens) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| [Neovim](#neovim) | Partial (semantic tokens) | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [Helix](#helix) | None yet | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [Emacs](#emacs) | Comments only | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [Sublime Text](#sublime-text) | Full (TextMate grammar) | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [JetBrains IDEs](#jetbrains-ides) | Partial (semantic tokens), full with the TextMate bundle | ✓ | ✓ | ✓ | ✓ | ✓ | — |

- **Partial highlighting** comes from the server's semantic tokens: sigils and names (`@flour`, `#bowl`, `&dough`), braces, modifiers, actions and comments are colored, the inside of braces (quantities, durations, temperatures) is not. It also waits for the server to answer, a moment after the file opens.
- **The preview** of the recipe and the <Term id="runSheet" /> is only in VS Code for now.
- A Zed extension is planned.

## Install the server

Every editor except VS Code starts the server as a command. Install it once:

```bash
npm install -g @gram-lang/language-server
```

The configurations below start `gram-language-server --stdio`. With the CLI already installed, `gram lsp` starts the same server: replace the command with it if you prefer.

Every configuration also sends `views: false`: these editors have no preview panel, so the server renders no view and sends only the standard LSP features.

An editor started from a desktop menu does not always see the `PATH` of your shell. If it does not find `gram-language-server`, give it the full path printed by `which gram-language-server` (`where gram-language-server` on Windows).

## VS Code and its forks

Install the **Gram - Recipe Language** extension from the [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=gram-lang.gram-lang), or from [Open VSX](https://open-vsx.org/extension/gram-lang/gram-lang) for VSCodium, Cursor, Windsurf or Positron. It bundles the server: nothing else to install. See [VS Code extension](/docs/reference/tooling/vscode-extension/).

- Completion is Neovim's own: <kbd>Ctrl</kbd>+<kbd>x</kbd> <kbd>Ctrl</kbd>+<kbd>o</kbd>, then <kbd>Ctrl</kbd>+<kbd>y</kbd> to accept. An ingredient whose name has several words comes with its braces, the cursor between them (`@Wheat flour{}`).
- The other features use Neovim's default mappings: <kbd>K</kbd> for hover, `grn` to rename a reference, `gra` for code actions, `:lua vim.lsp.buf.format()` to format, `gc` to comment out with `//`.

With Neovim 0.10, the same settings go through [nvim-lspconfig](https://github.com/neovim/nvim-lspconfig), which has no entry for Gram: this configuration is not maintained for it.

Tested with Neovim 0.11.6 and 0.12.6.

- <kbd>M-x</kbd> `eglot` starts the server in a recipe; add `(add-hook 'gram-mode-hook #'eglot-ensure)` to start it on every `.gram` file.
- Then diagnostics show through Flymake, hover in the echo area, completion with <kbd>C-M-i</kbd> (or Corfu, Company), and <kbd>M-x</kbd> `eglot-format-buffer` and `eglot-rename` format and rename.

## Sublime Text

Sublime Text needs three things: the Gram syntax, the comment settings and the [LSP](https://packagecontrol.io/packages/LSP) package.

1. Install the **LSP** package with Package Control.
2. Open your `User` folder (**Preferences › Browse Packages…**, then `User`) and save in it:
   - the Gram syntax, `gram.tmLanguage`, shipped by the `@gram-lang/parser` package: [download it from jsDelivr](https://cdn.jsdelivr.net/npm/@gram-lang/parser/syntaxes/gram.tmLanguage). Sublime Text picks it for `.gram` files on its own;

## JetBrains IDEs

IntelliJ IDEA, WebStorm, PyCharm and the other JetBrains IDEs run the server through the [LSP4IJ](https://plugins.jetbrains.com/plugin/23257-lsp4ij) plugin.

1. Install **LSP4IJ** from the plugin marketplace.
2. In **Settings › Languages & Frameworks › Language Servers**, add a server (**+**):
   - **Server** tab: name `Gram`, command `gram-language-server --stdio`;
   - **Mappings** tab, **File name patterns**: the pattern `*.gram`, language id `gram`;
   - **Configuration** tab, **Initialization Options**:

<Code code={jetbrains} lang="json" themes={{ light: 'github-light', dark: 'github-dark' }} />

3. Recommended: add the TextMate bundle, without which quantities, durations and temperatures stay uncolored. Download the extension's `.vsix` from [Open VSX](https://open-vsx.org/extension/gram-lang/gram-lang), unzip it (it is a zip archive), then in **Settings › Editor › TextMate Bundles**, add (**+**) its `extension` folder.

Then check, in a project that has a `.gram/ingredients.yaml`:

- [ ] a `.gram` file opens with the server started (**Language Servers** tool window);
- [ ] sigils, names and references are colored, and quantities too with the TextMate bundle;
- [ ] an error in the recipe shows as a diagnostic;
- [ ] typing `@` offers the ingredients of the database;
- [ ] hovering an ingredient shows its details;
- [ ] **Reformat Code** and **Rename** work on a reference (`&dough`).
