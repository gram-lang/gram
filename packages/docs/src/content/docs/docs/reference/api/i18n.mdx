Shared unit/time normalization and UI-string dictionaries, used internally across the pipeline (the parser doesn't normalize units — that happens in `@gram-lang/kitchen`'s scaling engine and `@gram-lang/analyzer`'s mass standardization) so `"càs"`, `"tbsp"`, and `"cuillère à soupe"` are all recognized as the same unit regardless of which locale a recipe or a database entry was written in.

## Canonical units & aliases

`normalizeUnit` maps any recognized alias (English or French, case-insensitive) to its canonical short form:

<GeneratedTable table={unitsTable("en")} />

```typescript
function normalizeUnit(rawUnit: string | undefined | null, lang?: string): string
```

```typescript
import { normalizeUnit } from '@gram-lang/i18n';

normalizeUnit('càs');              // "tbsp"
normalizeUnit('Tablespoons');      // "tbsp"
normalizeUnit('kilo', 'fr');       // "kg" (language-scoped lookup, falls back to global)
```

Unrecognized input is returned lowercased and trimmed, unchanged.

## Time units

Same alias-normalization pattern, scoped to durations:

<GeneratedTable table={timeUnitsTable("en")} />

```typescript
function resolveTimeUnit(unit?: string | null, lang?: string): string
```

```typescript
import { resolveTimeUnit } from '@gram-lang/i18n';

resolveTimeUnit('minutes'); // "m"
resolveTimeUnit('heures', 'fr'); // "h"
```

## Default ingredient categories

Used by `gram shop` and other consumers to group a shopping list by culinary family when an ingredient's database entry has no explicit `category`:

<GeneratedTable table={categoriesTable("en")} />

`CATEGORY_KEYS` exports stable, locale-invariant category keys (`produce`, `dairy`, `meat`, `pantry`, ...), and `getCategoryLabels(lang)` resolves those keys to human-readable localized labels:

```typescript
function getDefaultCategories(lang?: string): string[] // defaults to 'en'
function getCategoryLabels(lang?: string): Record<CategoryKey, string>
```

```typescript
import { getDefaultCategories, getCategoryLabels, CATEGORY_KEYS } from '@gram-lang/i18n';

getDefaultCategories('fr'); // ["Légumes", "Fruits", "Viandes", ...]
getCategoryLabels('fr').produce; // "Légumes"
```

## Unit conversion tables

`@gram-lang/i18n` acts as the single source of truth for same-family unit conversion factors (`UNIT_CONVERSIONS`) and time-to-minute duration multipliers (`TIME_TO_MINUTES`):

```typescript
import { UNIT_CONVERSIONS, TIME_TO_MINUTES } from '@gram-lang/i18n';

UNIT_CONVERSIONS.mass.map.kg; // 1000 (grams)
UNIT_CONVERSIONS.volume.map.tbsp; // 14.7868 (mL)
TIME_TO_MINUTES.h; // 60 (minutes)
```

### Numbers in the reader's language

<Since v="1.4.1" />

`formatNumber` writes a number as a reader of the language does (`1.5` in English, `1,5` in French), rounded to two decimals by default and with no thousands separator, as a recipe writes `1500 g`. `localizeDecimals` does the same for a quantity already written as text (a range, a timer), and `decimalSeparator` gives the separator itself. Every view and the CLI write the numbers they show through these; a number read back by a script or a file (a `data-*` attribute, JSON, `.gram` source) keeps its point.

```typescript
import { formatNumber, localizeDecimals, decimalSeparator } from '@gram-lang/i18n';

formatNumber(1.5, 'fr');          // "1,5"
formatNumber(147.46, 'fr', 1);    // "147,5"
formatNumber(1500, 'en');         // "1500"
localizeDecimals('1.5-2', 'fr');  // "1,5-2"
decimalSeparator('fr');           // ","
```

Spoons, cups and imperial measures (tsp, tbsp, cup, tasse, oz, lb, pt...) are read in fractions: `toKitchenFraction` writes such a quantity as a whole number and a common fraction, as a cook writes it, so `1.75 cup` and `1 3/4 cup` both show `1 3/4 cup`. It returns `undefined` when no common fraction is near (`1.6`) and for any other unit: metric units and counts keep decimals. `isFractionUnit` tells whether a unit is one of them, `commonFraction` gives the fraction of a value below 1.

```typescript
import { toKitchenFraction, isFractionUnit, commonFraction } from '@gram-lang/i18n';

toKitchenFraction(1.75, 'cup');   // "1 3/4"
toKitchenFraction(0.5, 'tsp');    // "1/2"
toKitchenFraction(1.6, 'cup');    // undefined
toKitchenFraction(1.5, 'kg');     // undefined
isFractionUnit('tasse', 'fr');    // true
commonFraction(0.25);             // "1/4"
```

### Large amounts and metric weights

`toLargerMetricUnit` converts a metric mass (`mg`, `g`) or volume (`ml`, `cl`, `dl`) to `kg` or `l` once it reaches 1000 g or 1000 ml (rounded to two decimal places), and returns any other amount unchanged. Gram uses it for what is bought or read as a total, never for what is weighed (see [Kilograms to buy, grams to weigh](/docs/explanation/shopping-list-aggregation/#kilograms-to-buy-grams-to-weigh)). `isMetricMassUnit` checks whether a unit (including localized aliases) is a metric mass (`mg`, `g`, `kg`).

```typescript
function toLargerMetricUnit(value: number, rawUnit: string | undefined | null, lang?: string): { value: number; unit: string }
function isMetricMassUnit(rawUnit: string | undefined | null, lang?: string): boolean
```

```typescript
import { toLargerMetricUnit, isMetricMassUnit } from '@gram-lang/i18n';

toLargerMetricUnit(3900, 'g');   // { value: 3.9, unit: "kg" }
toLargerMetricUnit(150, 'cl');   // { value: 1.5, unit: "l" }
toLargerMetricUnit(999, 'g');    // { value: 999, unit: "g" }
toLargerMetricUnit(64, 'oz');    // { value: 64, unit: "oz" }
isMetricMassUnit('kilo', 'fr');  // true
isMetricMassUnit('lb');          // false
```
