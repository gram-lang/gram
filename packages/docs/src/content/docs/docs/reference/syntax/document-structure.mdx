A Gram recipe file (`.gram`) is structured into several distinct parts: Metadata, Sections, Steps, and Comments.

## 1. Metadata (frontmatter)

The frontmatter is a **YAML** block at the very start of the file, enclosed by `---`.

:::caution[Flat lines only]
It looks like YAML, but Gram only reads flat `key: value` lines (blank lines are fine), with lists written inline (`tags: ['brownie', 'matcha']`). A comment line (`# …`) or an indented line makes the whole block unreadable: it is then read as a step of text, with no metadata. A `#` at the end of a line is part of the value.
:::

The Gram parser accepts **any** key-value pair in this block: a key Gram does not know is your own metadata, shown as is in the recipe's byline. The keys below are Gram's own. **Functional** keys change what the compiler, the analyzer or the views compute; **informational** keys are shown, never computed with.

<GeneratedTable table={frontmatterKeysTable("en")} />

### Functional keys

*   `portions`: The baseline number of portions. Divides the [Nutritional Estimation](/docs/explanation/nutrition) into per-portion figures, and is rescaled alongside quantities when a recipe is scaled — so per-portion values stay the same whatever factor you apply. A trailing label (`portions: 4 servings`) is tolerated; a zero or negative count is ignored.
*   `densities`: Custom density overrides (g/mL) for specific `@ingredient` items, used by the [Mass Standardization](/docs/explanation/engine/kitchen) algorithm. Write them as `name:value` pairs in an inline list: `densities: [flour:0.55, milk:1.03]`.
*   `language`: The language the recipe is written in, as a [BCP 47](https://www.rfc-editor.org/info/bcp47) tag (see below).

### Recipe language (`language`)
<Since v="1.6.0" />

`language: fr` (or `en`, `fr-CA`, `pt-BR`…) says which language the recipe is written in. In the editor, Gram reads the unit words of that language when it scales the recipe by an ingredient, and writes the preview and the hints in it; the printed recipe carries it as the page's `lang`. It is the language of the recipe, not of your editor: a French recipe opened in an English editor keeps its French units and preview. `gram view` and the playground do not read it yet, and keep their own language (`--lang`, the language of the site).

### Deprecated keys
<Since v="1.6.0" type="deprecated" />

:::caution[Deprecated: `servings`, `yield` and `yields`]
`servings`, `yield` and `yields` are deprecated since 1.6.0 and will be removed in 2.0.0. Only the HTML recipe ever read them: they were shown, but ignored by scaling and the nutrition per portion. Write `portions` instead of `servings`, and `makes` instead of `yield` or `yields`. Until 2.0.0 they keep working, and the compiler raises a [`DEPRECATED_FRONTMATTER_KEY`](/docs/reference/api/warnings) warning (which fails `gram check --strict`); in an imported module, it shows on the `@use` line that imports it. When a key and its replacement are both written, the replacement wins.
:::

<CodeTabs>
```gram title="recipe.gram"
---
title: 'Matcha Brownies'
description: 'A simple Japanese-style matcha brownie...'
author: ["Auguste Kerflec"]
tags: ['brownie', 'matcha']
category: 'Dessert'
source: ['https://example.com/matcha-brownie']
makes: '20x20cm mold'

portions: 4
densities: [flour:0.55, milk:1.03]
---
```
</CodeTabs>

## 2. Module imports

Right after the frontmatter, before any step, a recipe can `@use` other `.gram` files as reusable sub-components.

```gram
@use "./bases/shortcrust-pastry.gram" as &pastry

## Assembly

[Line] The #pan{} with &pastry{250g}.
```

*See [Module Imports](/docs/reference/syntax/modules) for the full syntax, scaling rules, and encapsulation guarantees.*

## 3. Steps

Each paragraph in a Gram file represents a single cooking step. Steps are separated by one or more empty lines.

```gram
A step,
the same step.

A different step.
```

### Action verbs
Steps can optionally start with an **Action** enclosed in brackets `[]`. This highlights the primary method used in that step, making it easy to parse visually or programmatically.

```gram
[Mix] @flour and @water.

[Bake] In the #oven for ~{30min}.
```

:::tip[Name the action]
Starting steps with an action verb in brackets is strongly recommended, especially for timed steps: the <Term id="runSheet" /> and summary views rely on these actions to name each step clearly.
:::

## 4. Sections

Complex recipes often have multiple components (e.g., dough, filling, frosting) that are prepared separately. You can group steps into `## Section` blocks using Markdown-style headings (e.g., `## Dough`).

```gram
## Dough

[Mix] @flour{200g} and @water{100ml} together until smooth.

## Filling

[Combine] @cheese{100g} and @spinach{50g}, then season to taste.
```

A `##` with no title after it opens an untitled section: its steps are grouped apart from the previous ones, with no heading.

### Retro-planning (scheduling)
You can assign a preparation timeframe to a `## Section` by adding a `~timer`-like annotation anywhere in the title.

```gram
## Puff Pastry ~{-2d}
```
This tells the compiler that the "Puff Pastry" `## Section` should be prepared **2 days in advance**.
The offset is a negative duration in days, hours and minutes, written like a timer (`~{-2d}`, `~{-12h}`, `~{-1h30}`, `~{-1d 12h}`) — free text (e.g. `~{the day before}`) is not valid here and is flagged by the compiler.

*See [Times & Scheduling](/docs/reference/syntax/times#section-retro-planning) for the full syntax rules and error handling.*

### Section outputs (declarations)
If a `## Section` produces a sub-component that will be used later in the recipe, you can declare it using `->&` at the end of the title.

```gram
## Puff Pastry ->&dough
```
*See [Intermediate Variables](/docs/reference/syntax/intermediate-variables) for more details.*

## 5. Comments

You can add comments to explain instructions without affecting the compiled output.

**Inline Comments (`//`)**:
```gram
[Mash] @potato{2kg} until smooth // alternatively, boil 'em first.
```

**Block Comments (`/* ... */`)**:
```gram
[Add] Slowly pour in @milk{4 cup} /* TODO change units to litres */, keep mixing.
```

:::note[Comments vs YAML Notes]
Comments are preserved during compilation and are rendered alongside the instructions (typically in grey italics). They are perfect for small, step-specific tips. However, if you have global observations or general feedback about the recipe (e.g., "Decrease sugar next time", "Best served cold"), it is recommended to put them in the YAML Frontmatter under the `notes` key so they can be displayed prominently at the top.
:::
