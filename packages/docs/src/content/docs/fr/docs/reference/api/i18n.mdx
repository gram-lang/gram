Ce package centralise la normalisation des unités, des durées et les dictionnaires de chaînes d'interface, exploités en interne par tout le pipeline (le parseur ne normalise pas les unités : cette étape a lieu lors du redimensionnement dans `@gram-lang/kitchen` et de la standardisation des masses dans `@gram-lang/analyzer`). Le but : que `"càs"`, `"tbsp"` et `"cuillère à soupe"` soient toujours reconnus comme la même unité, quelle que soit la langue de rédaction de la recette ou de la base de données.

## Unités canoniques & alias

`normalizeUnit` fait correspondre tout alias reconnu (anglais ou français, insensible à la casse) à sa forme canonique courte :

<GeneratedTable table={unitsTable("fr")} />

```typescript
function normalizeUnit(rawUnit: string | undefined | null, lang?: string): string
```

```typescript
import { normalizeUnit } from '@gram-lang/i18n';

normalizeUnit('càs');              // "tbsp"
normalizeUnit('Tablespoons');      // "tbsp"
normalizeUnit('kilo', 'fr');       // "kg" (recherche ciblée par langue, avec repli sur le dictionnaire global)
```

Une unité non reconnue est simplement retournée en minuscules, sans ses espaces superflus.


## Unités de temps

Le même principe de normalisation via alias, appliqué cette fois aux durées :

<GeneratedTable table={timeUnitsTable("fr")} />

```typescript
function resolveTimeUnit(unit?: string | null, lang?: string): string
```

```typescript
import { resolveTimeUnit } from '@gram-lang/i18n';

resolveTimeUnit('minutes'); // "m"
resolveTimeUnit('heures', 'fr'); // "h"
```

## Catégories d'ingrédients par défaut

Catégories de repli exploitées par `gram shop` (et d'autres consommateurs) pour regrouper la liste de courses par famille culinaire, lorsqu'un ingrédient de la base n'a pas de `category` explicite :

<GeneratedTable table={categoriesTable("fr")} />

`CATEGORY_KEYS` exporte les clés stables, invariantes par langue (`produce`, `dairy`, `meat`, `pantry`, ...). La fonction `getCategoryLabels(lang)` permet ensuite de résoudre ces clés en libellés traduits :

```typescript
function getDefaultCategories(lang?: string): string[] // par défaut 'en'
function getCategoryLabels(lang?: string): Record<CategoryKey, string>
```

```typescript
import { getDefaultCategories, getCategoryLabels, CATEGORY_KEYS } from '@gram-lang/i18n';

getDefaultCategories('fr'); // ["Légumes", "Fruits", "Viandes", ...]
getCategoryLabels('fr').produce; // "Légumes"
```

## Tables de conversion d'unités

`@gram-lang/i18n` fait office de source de vérité unique (*Single Source of Truth*) pour les facteurs de conversion intra-famille (`UNIT_CONVERSIONS`) et les multiplicateurs de durée en minutes (`TIME_TO_MINUTES`) :

```typescript
import { UNIT_CONVERSIONS, TIME_TO_MINUTES } from '@gram-lang/i18n';

UNIT_CONVERSIONS.mass.map.kg; // 1000 (grammes)
UNIT_CONVERSIONS.volume.map.tbsp; // 14.7868 (mL)
TIME_TO_MINUTES.h; // 60 (minutes)
```

### Les nombres dans la langue du lecteur

<Since v="1.4.1" />

`formatNumber` écrit un nombre comme un lecteur de la langue l'écrit (`1.5` en anglais, `1,5` en français), arrondi par défaut à deux décimales et sans séparateur de milliers, comme une recette écrit `1500 g`. `localizeDecimals` fait de même pour une quantité déjà écrite en texte (une fourchette, un minuteur), et `decimalSeparator` donne le séparateur lui-même. Toutes les vues et le CLI écrivent les nombres qu'ils affichent avec ces fonctions ; un nombre relu par un script ou un fichier (un attribut `data-*`, du JSON, la source `.gram`) garde son point.

```typescript
import { formatNumber, localizeDecimals, decimalSeparator } from '@gram-lang/i18n';

formatNumber(1.5, 'fr');          // "1,5"
formatNumber(147.46, 'fr', 1);    // "147,5"
formatNumber(1500, 'en');         // "1500"
localizeDecimals('1.5-2', 'fr');  // "1,5-2"
decimalSeparator('fr');           // ","
```

Les cuillères, les tasses et les mesures impériales (tsp, tbsp, cup, tasse, oz, lb, pt...) se lisent en fractions : `toKitchenFraction` écrit une telle quantité sous la forme d'un entier suivi d'une fraction courante, comme l'écrit un cuisinier, si bien que `1.75 cup` et `1 3/4 cup` s'affichent tous deux `1 3/4 cup`. La fonction renvoie `undefined` quand aucune fraction courante n'est proche (`1.6`) et pour toute autre unité : les unités métriques et les quantités sans unité gardent leurs décimales. `isFractionUnit` indique si une unité en fait partie, `commonFraction` donne la fraction d'une valeur inférieure à 1.

```typescript
import { toKitchenFraction, isFractionUnit, commonFraction } from '@gram-lang/i18n';

toKitchenFraction(1.75, 'cup');   // "1 3/4"
toKitchenFraction(0.5, 'tsp');    // "1/2"
toKitchenFraction(1.6, 'cup');    // undefined
toKitchenFraction(1.5, 'kg');     // undefined
isFractionUnit('tasse', 'fr');    // true
commonFraction(0.25);             // "1/4"
```

### Grandes quantités et poids métriques

`toLargerMetricUnit` convertit une masse (`mg`, `g`) ou un volume (`ml`, `cl`, `dl`) métrique en `kg` ou en `l` dès 1000 g ou 1000 ml (arrondi à deux décimales), et renvoie toute autre quantité telle quelle. Gram l'utilise pour ce qu'on achète ou qu'on lit comme un total, jamais pour ce qu'on pèse (voir [On achète en kilos, on pèse en grammes](/fr/docs/explanation/shopping-list-aggregation/#on-achète-en-kilos-on-pèse-en-grammes)). `isMetricMassUnit` vérifie si une unité (alias localisés compris) est une masse métrique (`mg`, `g`, `kg`).

```typescript
function toLargerMetricUnit(value: number, rawUnit: string | undefined | null, lang?: string): { value: number; unit: string }
function isMetricMassUnit(rawUnit: string | undefined | null, lang?: string): boolean
```

```typescript
import { toLargerMetricUnit, isMetricMassUnit } from '@gram-lang/i18n';

toLargerMetricUnit(3900, 'g');   // { value: 3.9, unit: "kg" }
toLargerMetricUnit(150, 'cl');   // { value: 1.5, unit: "l" }
toLargerMetricUnit(999, 'g');    // { value: 999, unit: "g" }
toLargerMetricUnit(64, 'oz');    // { value: 64, unit: "oz" }
isMetricMassUnit('kilo', 'fr');  // true
isMetricMassUnit('lb');          // false
```
