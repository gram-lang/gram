Gère le rendu d'un `CompilationResult` (ou d'un `AnalyzedCompilationResult`) en Markdown, en HTML, en un document HTML autonome optimisé pour l'impression, ou en texte brut. Si vous construisez une interface front-end native (React, Vue, Svelte, etc.), vous consommerez le plus souvent le JSON directement. Consultez le guide [Créer une UI personnalisée](/fr/docs/how-to/build-custom-ui).

## `toMarkdown` / `toHTML` / `toPrintHTML` / `toText`

```typescript
type RenderableCompilationResult = CompilationResult | AnalyzedCompilationResult;

function toMarkdown(data: RenderableCompilationResult, options?: RendererOptions): string
function toHTML(data: RenderableCompilationResult, options?: RendererOptions): string
function toPrintHTML(data: RenderableCompilationResult, options?: RendererOptions): string
function toText(data: RenderableCompilationResult, options?: RendererOptions): string
```

```typescript
import { compile } from '@gram-lang/kitchen';
import { toHTML } from '@gram-lang/renderer';

const compiled = compile(ast);
const html = toHTML(compiled, { lang: 'fr' });
```

`toPrintHTML` génère un document HTML complet et autonome (`<style>` inline, règles `@page` A4, aucune dépendance externe), idéal pour les fonctionnalités d'export PDF ou d'impression papier. À l'inverse, `toHTML` retourne un fragment HTML conçu pour s'intégrer discrètement dans une mise en page existante.

`toText` écrit la recette en texte brut, pour un terminal ou un simple fichier : un cadre avec le titre, les portions et les durées, puis la liste de courses, le matériel, chaque section (ses ingrédients, puis ses étapes numérotées), les notes et la nutrition. Rien n'y est échappé ni balisé, et les libellés viennent de `@gram-lang/i18n`. C'est le format `text` de la vue recette (`render("recipe", input, "text")`) : ce qu'affiche `gram view` et ce qu'écrit `gram export --format text`. Les couleurs restent l'affaire de l'outil qui l'affiche, via `textStyle` :

```typescript
import chalk from 'chalk';
import { toText } from '@gram-lang/renderer';

const text = toText(compiled, {
  lang: 'fr',
  width: process.stdout.columns,
  textStyle: { title: chalk.bold, ingredient: chalk.yellow, dim: chalk.dim },
});
```

Ces quatre formateurs partagent la même architecture de traversée (`RenderBackend`). Cela garantit que les résumés nutritionnels, les notes de bas de page, les badges de masse brute ou les avertissements d'unités incompatibles sont restitués de manière rigoureusement homogène, que vous cibliez du Markdown, du HTML, du Print ou du texte brut.

### `RendererOptions`

| Option | Type | Description |
|---|---|---|
| `icons` | `RendererIcons` | Surcharge tout ou partie des icônes par défaut (voir `DEFAULT_ICONS` ci-dessous). |
| `classes` | `RendererClasses` | Surcharge les noms de classes CSS appliquées aux éléments générés (HTML/print uniquement). |
| `formatFraction` | `(value: number) => string` | Écrit toutes les quantités numériques des vues recette (étapes, ingrédients de section, liste de courses) à la place du comportement par défaut : un entier, une fraction courante en cuisine (`0.5` → `"1/2"`) ou un nombre décimal dans la `lang` des options (`1.5` → `"1,5"` en français). La fonction ne reçoit que le nombre : c'est à elle de gérer la langue. Les masses standardisées, les kilos de la liste de courses, les valeurs nutritionnelles et le plan de marche gardent le comportement par défaut. |
| `formatDuration` | `(minutes: number) => string` | Formateur de durée personnalisé (par défaut, ex. : `90` → `"1 h 30 min"`, dans la `lang` des options). |
| `hideStepQty` | `boolean` | Masque les quantités au sein du texte narratif des étapes (la liste de courses et les listes d'ingrédients de section restent intactes). Par défaut, tous les formats affichent la quantité immédiatement après chaque ingrédient, accompagnée de sa masse standardisée quand elle apporte une précision utile : `farine (250 ml, ~148 g)`. En HTML, elle est balisée par un `<span class="step-quantity">` (`classes.stepQuantity`), l'infobulle détaillant les conversions. |
| `miseEnPlace` | `'perSection' \| 'upfront' \| 'perDay'` | Stratégie d'ordonnancement suivie par le document : préparation immédiatement avant chaque section (`'perSection'`, par défaut), regroupée tout au début de la recette (`'upfront'`) ou au début de chaque journée de travail (`'perDay'`). Détermine le temps total affiché en en-tête. Le texte de la recette n'expose aucun ordonnancement temporel : la planification détaillée et la liste des éléments à mobiliser figurent dans le <Term id="runSheet" /> (`runSheet`). La chronologie est déduite à la volée depuis le graphe `tasks`. |
| `rests` | `'shortest' \| 'balanced' \| 'longest'` | Élasticité appliquée aux minuteurs passifs définis par un intervalle (`~_{12-24h}`) : borne la plus courte (`'shortest'`, par défaut), médiane (`'balanced'`) ou borne la plus longue (`'longest'`). Les minuteurs passifs à durée fixe et les minuteurs actifs ne sont pas affectés. Pilote les mêmes durées que `miseEnPlace`. |
| `comments` | `'show' \| 'hide'` | Affiche (`'show'`, par défaut) ou masque (`'hide'`) les commentaires de la recette (`// comme ceci`) : les notes isolées sur leur propre ligne comme celles en fin de ligne (qui deviennent des notes de bas de page dans les vues Recette). Cette option s'applique de façon uniforme à toutes les vues, plan de marche compris. |
| `bakersMathOnly` | `boolean` | N'affiche que les pourcentages du boulanger, en masquant les quantités absolues. |
| `interactiveScaling` | `boolean` | <Since type="deprecated" v="1.4.0" /> Ajoute un sélecteur de portions dans l'en-tête de la recette HTML, dont les boutons ne marchent que si la page qui l'accueille les prend en charge. Mettez plutôt la recette à l'échelle avant de l'afficher : la vue montre d'elle-même les portions obtenues et le facteur (`×1,5`). Retiré en 2.0.0. |
| `nutritionBasis` | `'auto' \| 'total' \| 'perPortion' \| 'per100g'` | Référentiel nutritionnel affiché. `'auto'` (par défaut) montre pour 100 g et par portion côte à côte (par portion seulement si la recette déclare des portions), la recette entière en dessous, en HTML, en Markdown comme en texte. |
| `interactiveNutrition` | `boolean` | <Since type="deprecated" v="1.4.0" /> N'a plus aucun effet : la recette HTML montre toutes les bases nutritionnelles côte à côte dans un tableau. Retiré en 2.0.0. |
| `lang` | `string` | Code de langue (ex. : `'en'`, `'fr'`) pour la traduction des libellés UI via `@gram-lang/i18n`. |
| `renderId` | `string` | Préfixe pour les identifiants d'ancres de notes de bas de page — utile pour éviter les collisions lors du rendu de plusieurs recettes sur une même page. |
| `textStyle` | `TextStyle` | Texte brut uniquement : la façon de faire ressortir chaque élément, avec une fonction par élément (`title`, `heading`, `dim`, `ingredient`, `reference`, `cookware`, `timer`, `action`). Chacune reçoit un morceau de texte et le rend mis en forme, sans en changer la largeur visible (les couleurs d'un terminal, par exemple). Un élément absent reste tel quel : le renderer ne dépend ainsi d'aucune bibliothèque de terminal. |
| `width` | `number` | Texte brut uniquement : la largeur du cadre de titre et des filets de section (`78` par défaut, `DEFAULT_TEXT_WIDTH`). |

## Réglages

Les réglages d'une recette et de son affichage sont définis ici de façon centralisée, afin que chaque outil construit sur Gram propose les mêmes options : les options de la CLI, les clés de configuration `gram.*` de l'éditeur et les réglages du playground reposent tous sur ces descripteurs.

```ts
import {
  parseRecipeSettings,
  parseViewSettings,
  viewSettingsToRendererOptions,
  recipeSettingsToAnalyzerOptions,
  toHTML,
} from "@gram-lang/renderer";
import { analyze } from "@gram-lang/analyzer";

const view = parseViewSettings(userConfig); // toute valeur inconnue retombe sur sa valeur par défaut
const recipe = parseRecipeSettings(userConfig);
const analyzed = analyze(compiled, db, recipeSettingsToAnalyzerOptions(recipe));
const html = toHTML(analyzed.result, viewSettingsToRendererOptions(view));
```

| Export | Description |
|---|---|
| `VIEW_SETTINGS` | Réglages d'affichage : `miseEnPlace`, `rests`, `comments`, `nutritionBasis`, `bakersMathOnly`, `stepQuantities`, `clock` <Since v="1.5.0" />. |
| `RECIPE_SETTINGS` | Calculs de l'analyseur (tous activés par défaut) : `bakersMath`, `massStandardization`, `yieldCalculation`, `nutritionEstimation`. |
| `SETTINGS` | Combinaison des réglages de vue et de recette dans une seule liste. |
| `parseViewSettings(raw)`, `parseRecipeSettings(raw)` | Analysent les réglages depuis un objet de configuration quelconque ; chaque valeur absente ou inconnue prend sa valeur par défaut. |
| `DEFAULT_VIEW_SETTINGS`, `DEFAULT_RECIPE_SETTINGS` | Valeurs par défaut de l'ensemble des réglages. |
| `viewSettingsToRendererOptions(settings)` | Convertit les réglages de vue en `RendererOptions`. La base nutritionnelle automatique est omise : le tableau nutritionnel garde ainsi toutes les bases côte à côte. |
| `recipeSettingsToAnalyzerOptions(settings)` | Convertit les réglages de recette en options pour l'analyseur (`enableBakersMath`, ...). |

Chaque descripteur expose sa clé (`key`), sa catégorie (`kind` : `"view"` ou `"recipe"`), son type (`"choice"` avec ses `values`, ou `"flag"`), sa valeur par défaut (`default`), sa description (`description`), ainsi que ses fonctions de validation et d'analyse (`accepts(raw)`, `parse(raw)`).

## Icônes

```typescript
import { DEFAULT_ICONS, toHTML } from '@gram-lang/renderer';

const html = toHTML(compiled, {
  icons: { ...DEFAULT_ICONS.html, clock: '<svg class="my-clock-icon">...</svg>' },
});
```

`DEFAULT_ICONS` propose deux variantes complètes : `DEFAULT_ICONS.html` (éléments SVG Phosphor autonomes intégrés en ligne) et `DEFAULT_ICONS.md` (emojis). Elles couvrent l'intégralité des identifiants de `RendererIcons` (`hourglass`, `timer`, `thermometer`, `caretRight`, `arrowRight`, `arrowUDownLeft`, `arrowElbowDownRight`, `warning`, `pencilSimple`, `minus`, `plus`, `clock`, `clockCounterClockwise`, `fire`, `knife`, `scales`, `package`, `info`). Chaque glyphe peut être personnalisé individuellement via `options.icons`.

## Utilitaires de formatage

Une série d'utilitaires de bas niveau (exploités en interne par les moteurs de rendu) est exportée pour faciliter la conception de moteurs de rendu personnalisés conformes aux conventions du langage :

```typescript
function formatDecimalToFraction(value: unknown, unit?: string, style?: { lang?: string; formatFraction?: (value: number) => string }): string   // 0.5 -> "1/2", 1.5 -> "1,5" avec lang "fr"
function getQty(item: Record<string, unknown>, style?: { lang?: string; formatFraction?: (value: number) => string }): { value: number | string | null; text?: string; isRelative?: boolean } | undefined
function formatQuantityValue(q: any, lang?: string): string                // Quantité de minuteur/température -> chaîne d'affichage, décimales dans `lang`
function formatDuration(minutes: number, lang?: string, options?: { days?: boolean }): string // 90 -> "1 h 30 min" (espace insécable entre le nombre et l'unité) ; à la seconde sous 1h (0.33 -> "20 s"), à la minute jusqu'à un jour (64.5 -> "1 h 5 min"), à l'heure au-delà (1506 -> "1 j 1 h", "1 d 1 h" en anglais)
function formatDurationRange(min: number, max: number, lang?: string, options?: { days?: boolean }): string // (45, 60) -> "45 min – 1 h", (60, 120) -> "1–2 h" ; Gram sait le relire
function formatTimerDuration(timer: { raw?: string; quantity?: unknown; unit?: string | null; minutes?: number }, lang?: string, format?: (minutes: number) => string): string // un minuteur compilé tel que les vues l'affichent : { minutes: 90 } -> "1 h 30 min", tel qu'écrit s'il est refusé ({ raw: "1:30" } -> "1:30") ; avec `format` (votre formatDuration), chaque bout d'une fourchette en entier
function formatTimer(item: { quantity?: unknown; unit?: string | null }, separator?: string): string   // { quantity: 1, unit: "h" } -> "1h" (le minuteur tel qu'écrit ; les vues passent par formatTimerDuration)
function toCommonFraction(value: number): string | undefined   // 0.25 -> "1/4", 0.3 -> undefined
function escapeHtml(unsafe: string | null | undefined): string
function escapeMarkdownHtml(unsafe: string | null | undefined): string   // neutralise `<`/`&` pour un rendu Markdown vers HTML sûr en aval
function joinStepTokens(tokens: StepToken[], renderToken: (token: StepToken) => string, isSpaceable: (token: StepToken) => boolean): string
```

### `formatUsageQuantity` <Since v="1.5.0" />

`formatUsageQuantity` écrit la quantité d'un ingrédient, d'une référence ou d'une entrée de liste de courses de la même façon que les vues, à partir de ses termes (`parts`, ou `qty` / `unit`) : telle qu'écrite quand Gram n'a rien changé (`1 cup + 1 tbsp`), recalculée quand la recette est mise à l'échelle ou pour une liste de courses (`2 cup + 2 tbsp`, jamais `34 tbsp` ; les fourchettes par leurs bornes). `gram shop` et `gram scale` s'en servent aussi. Voir [mettre à l'échelle une somme de quantités](/fr/docs/explanation/scaling/#mettre-à-léchelle-une-somme-de-quantités).

```typescript
function formatUsageQuantity(item: Record<string, unknown>, ctx?: QuantityContext): string
interface QuantityContext { lang?: string; formatFraction?: (value: number) => string; scaled?: boolean; buying?: boolean }

formatUsageQuantity({ qty: 34, unit: 'tbsp' }, { buying: true });                       // "2 cup + 2 tbsp"
formatUsageQuantity({ qty: 13.5, unit: 'tbsp', range: { min: 13, max: 14 } }, { buying: true }); // "13-14 tbsp"
```

## Le plan de marche

À partir de l'objet `RunSheet` produit par `runSheet()` (`@gram-lang/scheduler`) et de la recette compilée, le renderer décline le plan de marche en quatre formats de sortie et expose les briques d'extraction sous-jacentes :

```typescript
import { project, runSheet } from '@gram-lang/scheduler';
import {
  runSheetToText, runSheetToMarkdown, runSheetToHTML, runSheetToPrintHTML,
  describeRunSheet, visitKit, sectionProgram,
} from '@gram-lang/renderer';

const context = { serveAt: '2026-10-17T20:00', timeZone: 'Europe/Paris', availability };
const sheet = runSheet(project([{ graph: compiled.tasks }], context), { graph: compiled.tasks, context });

runSheetToText(sheet, compiled, { lang: 'fr' });      // texte brut
runSheetToMarkdown(sheet, compiled, { lang: 'fr' });  // Markdown, listes à cocher en - [ ]
runSheetToHTML(sheet, compiled, { lang: 'fr' });      // fragment HTML, sans script
runSheetToPrintHTML(sheet, compiled, { lang: 'fr' }); // document d'impression autonome, un jour par page
const model = describeRunSheet(sheet, compiled);       // le plan en mots, sous forme de données
```

Le plan de marche d'une recette sans heure de service cible s'obtient via `runSheet(compiled.schedule, { graph: compiled.tasks })` (ou depuis `layout(...).schedule`) : les journées y sont désignées de manière relative (`J-2`, `J-1`, `Jour J`), les créneaux correspondent à des durées d'attente relatives, et aucune marge horaire absolue n'est calculée.

### `RunSheetRenderOptions`

| Option | Type | Description |
|---|---|---|
| `lang` | `string` | Code de langue (`'en'`, `'fr'`) pour les libellés et le format des dates. |
| `roundTo` | `number` | Affichage uniquement : arrondi des heures à N minutes (par défaut : `5`). Les calculs internes restent exacts. |
| `formatDuration` | `(minutes: number) => string` | Formateur de durée personnalisé. |
| `hourCycle` <Since v="1.5.0" /> | `'h23' \| 'h12'` | La façon d'écrire l'heure : `'h23'` (par défaut, `13:00`) ou `'h12'` (`1:00 PM`, avec les marques de la langue de `lang`). Lue aussi par `describeServeTimes()` et `describeEarliestServe()`. `prepareViews()` la déduit du réglage `clock`. |
| `comments` | `'show' \| 'hide'` | Affiche (par défaut) ou masque les commentaires de la recette dans les étapes. Lorsqu'ils sont affichés, une note isolée sur une ligne se place sous son étape et une note en fin de ligne reste intégrée à la phrase, entre parenthèses ; le rendu HTML les distingue discrètement en petits caractères grisés. |

### `RunSheetModel`

`describeRunSheet()` retourne :

| Champ | Description |
|---|---|
| `title`, `subtitle`, `summary` | « Plan de marche — Entremets », « Pour le samedi 17 octobre à 20:00 · 6 portions », « 3 jours · 3 passages en cuisine · 45m de travail en tout ». |
| `problems` | Diagnostics contextuels émis si des contraintes de calendrier n'ont pas pu être respectées (une phrase explicative par problème). |
| `schedule[]` | Synthèse des journées : une ligne par passage actif (`kind: 'visit'`), par processus passif en continu (`'thread'`) et pour le service final (`'serve'`), avec les propriétés `day`, `time` et `text`. |
| `days[]` | Détail par journée : en-tête (`heading`), créneau horaire (`slot`), avertissements de repos ajustés (`notices`) et liste des passages (`visits[]`), chacun détaillant son créneau (`slot`), sa marge d'anticipation (`margin`), ses ingrédients et matériel (`kit[]`, regroupé par catégories, renseigné dans les modes `perDay` et `upfront`), les sections à réaliser (`program[]` : une section, ses étapes `steps[]` numérotées comme dans la recette avec leur action, en HTML, en Markdown et en texte, son heure de début (`startTime`, avec une heure de service), un indicateur `continued` quand elle se poursuit depuis un passage précédent, son fichier source (`origin`) si elle est importée, un renvoi comme `étapes 1 à 3` et, en mode `perSection`, son propre `kit[]` de mise en place) et les tâches poursuivies en tâche de fond (`leaving[]`). |
| `events[]` | Un événement d'agenda par passage (`start`, `end` en UTC, `title`, `description`), pour un plan avec heure de service. |

### `visitKit()`, `sectionProgram()` et `sectionSteps()`

Trois fonctions d'extraction de haut niveau exploitées par le plan de marche sont exportées afin de faciliter leur réutilisation dans vos propres interfaces :

```typescript
visitKit(compiled, sections: number[], { lang?, madeBefore? }): KitItem[]
// { kind: 'ingredient' | 'prepared' | 'cookware', name, quantity?, detail?, mass?, note? }

sectionProgram(compiled, section: number, stepIndexes: number[], { lang? }): SectionProgram | undefined
// { section, title, origin?, from, to }

sectionSteps(compiled, section: number, stepIndexes: number[], { lang?, comments?, formatDuration? }): ProgramStep[]
// { number?, action?, comment?, html, md, text } : une étape numérotée comme dans la vue Recette, ou une note isolée
```

### L'horloge du lecteur <Since v="1.5.0" />

Le réglage d'affichage `clock` (`'auto'`, `'12h'`, `'24h'`, `'auto'` par défaut) détermine comment le plan de marche et les horaires suggérés écrivent l'heure. C'est l'horloge de la personne qui lit, pas celle de la recette : `'auto'` suit la région de sa locale, que `prepareViews()` reçoit dans son option `locale` (`'en-US'`, `'fr-FR'`), distincte de `lang`, la langue des textes. Une locale dont la région écrit en 12 heures (`en-US`, `en-CA`, `en-AU`, `en-IN`) donne `1:00 PM` ; toutes les autres, une locale sans région (`'en'`) et l'absence de locale donnent `13:00`. Le moteur de rendu ne devine jamais : c'est la surface qui transmet la locale (le playground `navigator.language`, le CLI et le serveur de langage `systemLocale(process.env, process.platform)`). Quelle que soit l'horloge, les données restent en ISO local (`serveAt: "2026-10-11T13:00"`).

```typescript
import { prepareViews, resolveHourCycle, systemLocale } from '@gram-lang/renderer';

const views = prepareViews(compiled, { clock: 'auto' }, { lang: 'fr', locale: 'en-US', kitchen, serveAt });
views.hourCycle;                              // "h12" : le plan de marche écrit « 1:00 PM »
resolveHourCycle('auto', 'fr-FR');            // "h23"
systemLocale({ LANG: 'en_US.UTF-8' });        // "en_US.UTF-8"
```

| Export | Description |
|---|---|
| `resolveHourCycle(clock, locale)` | `'h12'` ou `'h23'` : l'horloge que nomme le réglage, sinon (`'auto'`) celle de `locale`. |
| `hourCycleOf(locale)` | L'horloge d'une locale, `'h23'` si elle ne précise pas de région ou ne se lit pas ; une locale POSIX (`en_US.UTF-8`) est lue comme sa balise BCP 47. |
| `systemLocale(env, platform?)` | La locale d'une machine : la première définie parmi `LC_ALL`, `LC_TIME` et `LANG` (`C` et `POSIX` n'en désignent aucune) ; sous Windows (`platform: 'win32'`), celle de l'environnement d'exécution. |
| `chooseClock(...choices)` | La première horloge réellement choisie, `'auto'` valant absence de choix : `chooseClock(option, reglageDuProjet)`. |
| `formatClock(hhmm, hourCycle, lang?)` | `"13:05"` écrit sur une horloge : tel quel en 24 heures, `"1:05 PM"` en 12. |
| `clockFormatOptions(hourCycle)` | Les options `Intl.DateTimeFormat` d'une heure sur cette horloge, pour un format qui écrit aussi la date. |

Rien n'est inventé : noms et quantités sont ceux du fichier `.gram`, et le plan de marche restitue fidèlement les étapes telles qu'elles figurent dans la recette. Le mode du kit (`perSection`, `perDay`, `upfront`) se lit dans `RunSheet.recipes[].miseEnPlace` (repris par `RunSheetModel.miseEnPlace`) : le moteur de rendu ne propose pas d'option dédiée pour ce réglage. `describeServeTimes()` et `describeEarliestServe()` formulent de la même façon en clair le résultat de `findServeTimes()` et `earliestServe()`.

## Diagramme de Gantt (`toGanttHTML` & `attachGanttInteractivity`) <Since type="deprecated" v="1.4.0" />

:::caution[Déprécié, retiré en 2.0.0]
Le diagramme de Gantt est remplacé par le [plan de marche](#le-plan-de-marche). Plus aucune interface de Gram (CLI, playground, extension VS Code) ne restitue de diagramme de Gantt. Les fonctions `toGanttHTML` et `attachGanttInteractivity`, les formateurs `formatTime` et `formatAxisTime`, les types `Gantt*` ainsi que la feuille de style `gantt.css` sont maintenus jusqu'en version 2.0.0. `toGanttHTML` émet un avertissement unique dans la console (`quiet: true` permet de le désactiver). Pour concevoir votre propre visualisation temporelle à partir des données de `runSheet()`, consultez le guide [Créer une interface sur mesure](/fr/docs/how-to/build-custom-ui/#construire-sa-propre-vue-planning) et la page [Dépréciations](/fr/docs/how-to/deprecations/).
:::

```typescript
import { toGanttHTML, attachGanttInteractivity } from '@gram-lang/renderer';

const ganttHtml = toGanttHTML(compiled, { lang: 'fr' });
container.innerHTML = ganttHtml;

const handle = attachGanttInteractivity(container, {
  timeMode: 'forward',   // 'forward' (chronomètre T+), 'reverse' (compte à rebours T-) ou 'target' (heure de service)
  targetTime: '19:30',
  isCompactMode: false
});
handle.dispose();
```

### `GanttRenderOptions`

| Option | Type | Description |
|---|---|---|
| `lang` | `string` | Code de langue pour les chaînes d'interface localisées. |
| `gapThresholdMinutes` | `number` | Durée d'inactivité minimale avant compression visuelle (par défaut : `60`). `Infinity` désactive la compression. |
| `compressedGapSize` | `number` | Largeur en minutes virtuelles à laquelle les creux compressés sont réduits (par défaut : `20`). |
| `miseEnPlace` | `'perSection' \| 'upfront' \| 'perDay'` | Stratégie de placement de la mise en place (par défaut : `'perSection'`). |
| `rests` | `'shortest' \| 'balanced' \| 'longest'` | Élasticité des minuteurs passifs en fourchette (par défaut : `'shortest'`). |
| `quiet` | `boolean` | Évite l'avertissement de dépréciation, émis une seule fois. |

### `GanttInteractivityOptions`

| Option | Type | Description |
|---|---|---|
| `timeMode` | `'forward' \| 'reverse' \| 'target'` | Mode d'affichage : temps écoulé (T+), compte à rebours (T-) ou heure réelle ancrée sur le service. |
| `targetTime` | `string` | Heure de service cible au format `"HH:MM"`. |
| `isCompactMode` | `boolean` | Bascule la hauteur des lignes en mode compact. |
