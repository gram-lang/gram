Gère le rendu d'un `CompilationResult` (ou d'un `AnalyzedCompilationResult`) en Markdown, en HTML, ou en un document HTML autonome optimisé pour l'impression. Si vous construisez une interface front-end native (React, Vue, Svelte, etc.), vous consommerez le plus souvent le JSON directement. Consultez le guide [Créer une UI personnalisée](/fr/docs/how-to/build-custom-ui).

## `toMarkdown` / `toHTML` / `toPrintHTML`

```typescript
type RenderableCompilationResult = CompilationResult | AnalyzedCompilationResult;

function toMarkdown(data: RenderableCompilationResult, options?: RendererOptions): string
function toHTML(data: RenderableCompilationResult, options?: RendererOptions): string
function toPrintHTML(data: RenderableCompilationResult, options?: RendererOptions): string
```

```typescript
import { compile } from '@gram-lang/kitchen';
import { toHTML } from '@gram-lang/renderer';

const compiled = compile(ast);
const html = toHTML(compiled, { lang: 'fr' });
```

`toPrintHTML` génère un document HTML complet et autonome (`<style>` inline, règles `@page` A4, aucune dépendance externe), idéal pour les fonctionnalités d'export PDF ou d'impression papier. À l'inverse, `toHTML` retourne un fragment HTML conçu pour s'intégrer discrètement dans une mise en page existante.

Ces trois formateurs partagent la même architecture de traversée (`RenderBackend`). Cela garantit que les résumés nutritionnels, les notes de bas de page, les badges de masse brute ou les avertissements d'unités incompatibles sont restitués de manière rigoureusement homogène, que vous cibliez du Markdown, du HTML ou du Print.

### `RendererOptions`

| Option | Type | Description |
|---|---|---|
| `icons` | `RendererIcons` | Surcharge tout ou partie des icônes par défaut (voir `DEFAULT_ICONS` ci-dessous). |
| `classes` | `RendererClasses` | Surcharge les noms de classes CSS appliquées aux éléments générés (HTML/print uniquement). |
| `formatFraction` | `(value: number) => string` | Fonction de formatage décimal → fraction personnalisée (gère par défaut les fractions courantes, ex. : `0.5` → `"1/2"`). |
| `formatDuration` | `(minutes: number) => string` | Formateur de durée personnalisé (par défaut, ex. : `90` → `"1h 30m"`). |
| `hideStepQty` | `boolean` | Masque les quantités d'ingrédients au sein du texte narratif des étapes (la liste de courses et les listes d'ingrédients de section restent intactes). |
| `miseEnPlace` | `'perSection' \| 'upfront' \| 'perSession'` | <Since v="1.4.0" /> La chronologie que suit le document : préparation immédiatement avant chaque section (`'perSection'`, par défaut), tout au début de la recette (`'upfront'`) ou au début de chaque journée de travail (`'perSession'`). Détermine les temps total et passif de l'en-tête. La recette elle-même ne montre aucun ordonnancement : quoi sortir, et quand, est dans le plan de travail (`runSheet`). La chronologie est calculée à partir de `tasks`. |
| `rests` | `'shortest' \| 'balanced' \| 'longest'` | <Since v="1.4.0" /> Élasticité appliquée aux minuteurs passifs définis par un intervalle (`~_{12-24h}`) : borne la plus courte (`'shortest'`, par défaut), médiane (`'balanced'`) ou borne la plus longue (`'longest'`). Les minuteurs passifs à durée fixe et les minuteurs actifs ne sont pas affectés. Pilote les mêmes durées que `miseEnPlace`. |
| `runSheet` | `RunSheet` | <Since v="1.4.0" /> Un plan de travail (`runSheet()` de `@gram-lang/scheduler`) à écrire après la recette, dans le même document (sous un titre Markdown dédié, ou mis en forme avec les styles d'impression). La recette dit comment, le plan dit quand : la recette elle-même se lit pareil avec ou sans lui. |
| `bakersMathOnly` | `boolean` | N'affiche que les pourcentages du boulanger, en masquant les quantités absolues. |
| `interactiveScaling` | `boolean` | Génère des contrôles interactifs d'ajustement des portions et ingrédients (HTML uniquement). |
| `nutritionBasis` | `'auto' \| 'total' \| 'perPortion' \| 'per100g'` | Référentiel nutritionnel affiché. `'auto'` (par défaut) sélectionne la portion si le nombre de portions est renseigné, sinon la recette entière. |
| `interactiveNutrition` | `boolean` | HTML uniquement : génère toutes les bases nutritionnelles disponibles sous un sélecteur interactif en CSS pur. Requiert la feuille de style du renderer ; ignoré si `nutritionBasis` force une base spécifique. |
| `lang` | `string` | Code de langue (ex. : `'en'`, `'fr'`) pour la traduction des libellés UI via `@gram-lang/i18n`. |
| `renderId` | `string` | Préfixe pour les identifiants d'ancres de notes de bas de page — utile pour éviter les collisions lors du rendu de plusieurs recettes sur une même page. |

## Diagramme de Gantt (`toGanttHTML` & `attachGanttInteractivity`) <Since type="deprecated" v="1.4.0" />

:::caution[Déprécié, retiré en 2.0.0]
Le diagramme de Gantt est remplacé par le [plan de travail](#le-plan-de-travail). Plus aucune surface de Gram (CLI, playground, VS Code) ne le dessine. `toGanttHTML`, `attachGanttInteractivity`, `formatTime`, `formatAxisTime`, les types `Gantt*` et `gantt.css` restent jusqu'en 2.0.0 ; `toGanttHTML` avertit une fois dans la console (`quiet: true` le fait taire pour un hôte qui dessine le graphique pour d'autres). Pour dessiner une chronologie vous-même, construisez-la à partir des données de `runSheet()` : voir [Construire sa propre interface](/fr/docs/how-to/build-custom-ui/#construire-sa-propre-vue-planning). Voir [Dépréciations](/fr/docs/how-to/deprecations/).
:::

```typescript
import { toGanttHTML, attachGanttInteractivity } from '@gram-lang/renderer';

const ganttHtml = toGanttHTML(compiled, { lang: 'fr' });
container.innerHTML = ganttHtml;

const handle = attachGanttInteractivity(container, {
  timeMode: 'forward',   // 'forward' (chronomètre T+), 'reverse' (compte à rebours T-) ou 'target' (heure de service)
  targetTime: '19:30',
  isCompactMode: false
});
handle.dispose();
```

### `GanttRenderOptions`

| Option | Type | Description |
|---|---|---|
| `lang` | `string` | Code de langue pour les chaînes d'interface localisées. |
| `gapThresholdMinutes` | `number` | Durée d'inactivité minimale avant compression visuelle (par défaut : `60`). `Infinity` désactive la compression. |
| `compressedGapSize` | `number` | Largeur en minutes virtuelles à laquelle les creux compressés sont réduits (par défaut : `20`). |
| `miseEnPlace` | `'perSection' \| 'upfront' \| 'perSession'` | Stratégie de placement de la mise en place (par défaut : `'perSection'`). |
| `rests` | `'shortest' \| 'balanced' \| 'longest'` | Élasticité des minuteurs passifs en fourchette (par défaut : `'shortest'`). |
| `quiet` | `boolean` | Évite l'avertissement de dépréciation, émis une seule fois. |

### `GanttInteractivityOptions`

| Option | Type | Description |
|---|---|---|
| `timeMode` | `'forward' \| 'reverse' \| 'target'` | Mode d'affichage : temps écoulé (T+), compte à rebours (T-) ou heure réelle ancrée sur le service. |
| `targetTime` | `string` | Heure de service cible au format `"HH:MM"`. |
| `isCompactMode` | `boolean` | Bascule la hauteur des lignes en mode compact. |

## Icônes

```typescript
import { DEFAULT_ICONS, toHTML } from '@gram-lang/renderer';

const html = toHTML(compiled, {
  icons: { ...DEFAULT_ICONS.html, clock: '<svg class="my-clock-icon">...</svg>' },
});
```

`DEFAULT_ICONS` propose deux variantes complètes : `DEFAULT_ICONS.html` (éléments SVG Phosphor autonomes intégrés en ligne) et `DEFAULT_ICONS.md` (emojis). Elles couvrent l'intégralité des identifiants de `RendererIcons` (`hourglass`, `timer`, `thermometer`, `caretRight`, `arrowRight`, `arrowUDownLeft`, `arrowElbowDownRight`, `warning`, `pencilSimple`, `minus`, `plus`, `clock`, `clockCounterClockwise`, `fire`, `knife`, `scales`, `package`, `info`). Chaque glyphe peut être personnalisé individuellement via `options.icons`.

## Utilitaires de formatage

Une série d'utilitaires de bas niveau (exploités en interne par les moteurs de rendu) est exportée pour faciliter la conception de moteurs de rendu personnalisés conformes aux conventions du langage :

```typescript
function formatDecimalToFraction(value: unknown): string   // 0.5 -> "1/2"
function getQty(item: Record<string, unknown>): { value: number | string | null; text?: string; isRelative?: boolean } | undefined
function formatQuantityValue(q: any): string                // Quantité de minuteur/température -> chaîne d'affichage
function formatDuration(minutes: number): string            // 90 -> "1h 30m" ; arrondi à la minute dès 1h, à la seconde en dessous (64.5 -> "1h 5m", 0.33 -> "20s")
function formatTimer(item: { quantity?: unknown; unit?: string | null }, separator?: string): string   // { quantity: 1, unit: "h" } -> "1h"
function toCommonFraction(value: number): string | undefined   // 0.25 -> "1/4", 0.3 -> undefined
function escapeHtml(unsafe: string | null | undefined): string
function escapeMarkdownHtml(unsafe: string | null | undefined): string   // neutralise `<`/`&` pour un rendu Markdown vers HTML sûr en aval
function joinStepTokens(tokens: StepToken[], renderToken: (token: StepToken) => string, isSpaceable: (token: StepToken) => boolean): string
```

## Le plan de travail

<Since v="1.4.0" />

À partir du `RunSheet` de `runSheet()` (`@gram-lang/scheduler`) et de la recette compilée, le renderer écrit le plan de travail en quatre formats, et expose les pièces dont il est fait :

```typescript
import { project, runSheet } from '@gram-lang/scheduler';
import {
  runSheetToText, runSheetToMarkdown, runSheetToHTML, runSheetToPrintHTML,
  describeRunSheet, passageKit, sectionProgram,
} from '@gram-lang/renderer';

const context = { serveAt: '2026-10-17T20:00', timeZone: 'Europe/Paris', availability };
const sheet = runSheet(project([{ graph: compiled.tasks }], context), { graph: compiled.tasks, context });

runSheetToText(sheet, compiled, { lang: 'fr' });      // texte brut
runSheetToMarkdown(sheet, compiled, { lang: 'fr' });  // Markdown, listes à cocher en - [ ]
runSheetToHTML(sheet, compiled, { lang: 'fr' });      // fragment HTML, sans script
runSheetToPrintHTML(sheet, compiled, { lang: 'fr' }); // document d'impression autonome, un jour par page
const model = describeRunSheet(sheet, compiled);       // le plan en mots, sous forme de données
```

Le plan d'une recette sans heure de service vient de `runSheet(compiled.schedule, { graph: compiled.tasks })` (ou de `layout(...).schedule`) : les jours sont `J-2`, `J-1`, `Jour J`, les créneaux sont des durées, et il n'y a pas de marge.

### `RunSheetRenderOptions`

| Option | Type | Description |
|---|---|---|
| `lang` | `string` | Code de langue (`'en'`, `'fr'`) pour les libellés et le format des dates. |
| `roundTo` | `number` | Affichage uniquement : arrondi des heures à N minutes (par défaut : `5`). Les calculs internes restent exacts. |
| `formatDuration` | `(minutes: number) => string` | Formateur de durée personnalisé. |
| `headingLevel` | `1 \| 2` | Markdown uniquement : niveau du titre du plan (`2` quand il suit une recette). |

### `RunSheetModel`

`describeRunSheet()` retourne :

| Champ | Description |
|---|---|
| `title`, `subtitle`, `summary` | « Plan de travail — Entremets », « Pour le samedi 17 octobre à 20:00 · 6 parts », « 3 jours · 3 passages en cuisine · 45m de travail en tout ». |
| `problems` | Ce que le plan n'a pas pu rendre faisable, une phrase chacun. |
| `schedule[]` | Le planning des jours : une ligne par passage (`kind: 'passage'`), par fil (`'thread'`) et le service (`'serve'`), avec `day`, `time` et `text`. |
| `days[]` | Par jour : `heading`, `slot`, `notices` (attentes ajustées) et `passages[]`, chacun avec `slot`, `margin`, `kit[]` (à sortir), `program[]` (au programme) et `leaving[]`. |
| `events[]` | Un événement d'agenda par passage (`start`, `end` en UTC, `title`, `description`), pour un plan avec heure de service. |

### `passageKit()` et `sectionProgram()`

Les deux extractions dont une vue de plan a besoin et qui lisent la recette compilée, exportées pour qu'une autre interface ne les réécrive pas :

```typescript
passageKit(compiled, sections: number[], { lang?, madeBefore? }): KitItem[]
// { kind: 'ingredient' | 'prepared' | 'cookware', name, quantity?, detail?, note? }

sectionProgram(compiled, section: number, stepIndexes: number[], { lang? }): SectionProgram | undefined
// { section, title, origin?, from, to, steps: [{ n, action?, temperatures, timers }] }
```

Rien n'est inventé : noms, quantités, actions, températures et minuteurs (avec leur fourchette écrite) sont ceux du fichier `.gram`. `describeServeTimes()` et `describeEarliestServe()` mettent de la même façon en mots le résultat de `findServeTimes()` et `earliestServe()`.
