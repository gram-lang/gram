Une recette malformée ou incomplète finit quand même de compiler : le compilateur et l'Analyseur collectent des objets `Warning` structurés au lieu de lever des exceptions. Cela permet d'afficher la recette tout en signalant visuellement les avertissements. L'énumération `WarningCode` et ses utilitaires sont exportés par `@gram-lang/kitchen`.

## L'interface `Warning`

```typescript
interface Warning {
  code: WarningCode;
  message: string;       // lisible par un humain, prêt à être affiché tel quel
  item?: string;
  loc?: { start: number; end: number }; // décalages en caractères dans la source, quand disponible
  section?: string | null;
  data?: Record<string, unknown>; // depuis la 1.5.0 : de quoi corriger (voir plus bas)
}
```

`compile()` les retourne dans le tableau `CompilationResult.warnings`. De son côté, `analyze()` les propage (et en ajoute potentiellement de nouveaux) dans `AnalyzedCompilationResult.warnings`. Ce ne sont jamais de simples chaînes de caractères : le champ `.message` est toujours garanti.

<Since v="1.5.0" /> Certains codes fournissent aussi un champ `data` structuré permettant aux outils et aux correctifs rapides du serveur de langage d'agir sans analyser `.message`. Seuls `INVALID_QUANTITY` (`{ reason, suggestion? }`), `OZ_AFTER_VOLUME` (`{ suggestion }`), `SPACED_COMPOSITE` (`{ suggestion }`, depuis la 1.5.2), `DEPRECATED_FRONTMATTER_KEY` (`{ key, suggestion, specifier? }`, depuis la 1.6.0), `REFERENCE_TO_INGREDIENT` (`{ suggestion }`, depuis la 1.6.0), `INVALID_DURATION` sur un minuteur (`{ suggestion }` quand Gram sait quoi proposer, depuis la 1.6.0) et `INVALID_UNIT` sur un ingrédient (`{ reason, suggestion? }`) renseignent `data`.

## Sévérité & `--strict`

```typescript
type WarningSeverity = "error" | "warning" | "info";
const warningSeverity: Record<WarningCode, WarningSeverity>;
```

Les problèmes d'intégrité structurelle (une référence vers un élément fantôme, une collision de noms, un module introuvable, etc.) sont de sévérité `error`. Les lacunes récupérables (estimations, annotations incomplètes) sont catégorisées en `warning`, et les simples notifications contextuelles (surplus, calcul par fournées, contention de ressources) sont en `info`. Ainsi, une unité de minuteur manquante n'interrompra pas l'exécution de la même façon qu'une référence indéfinie. C'est exactement sur cette distinction que repose l'option `--strict` de la commande CLI `gram check` : sans `--strict`, seuls les codes de sévérité `error` font échouer la commande ; avec, chaque `warning` et `info` est promu en `error`. Vous pouvez facilement coder votre propre logique de mode strict en vous appuyant sur le dictionnaire `warningSeverity[code]`.

<Since v="1.6.0" /> `warningInfo` reprend cette sévérité et y ajoute ce qu'un outil doit encore savoir d'un code : `deprecated: true` signale un code qui repère une forme dépréciée (`DEPRECATED_FRONTMATTER_KEY`), que le serveur de langage affiche barrée. `warningInfoOf(code)`, exporté par `@gram-lang/modules`, la lit pour n'importe quel code, y compris ceux des modules.

```typescript
interface WarningCodeInfo { severity: WarningSeverity; deprecated?: true }
const warningInfo: Record<WarningCode, WarningCodeInfo>;
```


## Codes

<GeneratedTable table={warningCodesTable("fr")} />

### `VARIABLE_NOT_FOUND`
Une quantité relative référence une variable intermédiaire (`50% of &nom`) qui n'a été déclarée nulle part dans la recette comme sortie intermédiaire (`->&nom`). **Correction** : déclarez la variable avant de la référencer, ou corrigez la faute de frappe.

### `RELATIVE_QUANTITY_UNRESOLVED`
Une quantité relative cible un ingrédient (`50% of @nom`) qui n'est pas apparu plus tôt **dans la même section**. Attention, contrairement aux variables, les cibles relatives aux ingrédients sont scopées par section. **Correction** : déplacez l'ingrédient cible plus haut dans la même section, ou passez par une variable intermédiaire (`&nom`) si la portée doit être globale.

### `RELATIVE_QUANTITY_UNKNOWN_MASS`
Émis pendant l'analyse : la cible d'une quantité relative a bien été trouvée, mais sa propre masse est incalculable (unité/densité introuvable). Le pourcentage ne peut donc pas s'appliquer. **Correction** : attribuez à l'ingrédient cible une unité standardisable, ou renseignez sa densité / son `unit_weight` dans la base de données.

Pour une [proportion avec unités](/fr/docs/reference/syntax/relative-quantities/#proportions-avec-unités) (`1 / 100 g @&farine`, `~{15 min / 500 g @&rôti}`, <Since v="1.5.0" />), il inclut une `reason` pointant sur la proportion et laisse la quantité non résolue :
- `noTargetQuantity` : la cible n'a pas de quantité.
- `incompatibleUnits` : pièces incompatibles (`2 tranches` face à des gousses), poids face à une pièce nommée, ou mot après l'unité (`100 g de`).
- `missingDensity` / `missingUnitWeight` : la conversion entre poids et volume ou pièces requiert `density` ou `unit_weight` dans la base d'ingrédients.
- `wholeUseAmbiguous` / `producerMassUnknown` : pour une préparation utilisée en entier (`&pâte`), une autre section la consomme aussi ou la masse de sa section productrice est incomplète.
- `stepProducer` : la préparation utilisée en entier sort d'une étape (`Mélanger … ->&pâte`) et non d'une section entière, or Gram ne pèse que ce qu'une section produit. Indiquez la quantité utilisée (`&pâte{500 g}`), ou préparez-la dans sa propre section.

**Correction** : écrivez la proportion dans l'unité de la cible, renseignez `density` ou `unit_weight` dans la base, ou indiquez la quantité utilisée (`&pâte{500 g}`).

### `CIRCULAR_REFERENCE`
La quantité relative d'un ingrédient se cible elle-même (`@farine{50% of @farine}`). **Correction** : supprimez l'auto-référence (une quantité relative doit pointer vers un ingrédient ou une variable *différente*).

### `UNDEFINED_REFERENCE`
Une référence pure (`&nom`) ou un ingrédient référençable (`@&nom`) pointe vers un élément qui n'a jamais été enregistré en amont de la recette. **Correction** : introduisez l'ingrédient (sans `&`) avant de le référencer, ou corrigez la faute de frappe.

### `REFERENCE_TO_INGREDIENT`
<Since v="1.6.0" />

Une référence (`&farine`) désigne un ingrédient brut déjà écrit (`@farine{500 g}`) et non une préparation : `&` renvoie à ce qu'une étape ou une section produit (`->&pâte`), `@&` à une nouvelle mention d'un ingrédient. La recette compile comme avant. **Correction** : écrivez `@&farine` ; `data.suggestion` le contient, et la correction rapide du serveur de langage ajoute le `@`. Une préparation qui porte le nom d'un ingrédient (`Dorer le @poulet{1} ->&poulet.` puis `&poulet`), ou un nom importé par `@use … as &nom`, ne déclenche rien.

### `MISSING_UNIT`
Un `Timer` (minuteur) ou une `Temperature` a été écrit sans unité explicite (ex. `~{10}` au lieu de `~{10 min}`). **Correction** : ajoutez l'unité manquante.

### `INVALID_UNIT`
Émis dans quatre cas :
- **Unités de temps ou de température** : le mot qui suit un nombre dans un `Timer` ou une ancre de section n'est pas une unité de temps reconnue (`~{3 bananes}`), ou une `Temperature` utilise une unité autre que Celsius ou Fahrenheit. **Correction** : utilisez une unité de temps reconnue (`h`, `min`, `heures`, `hr`…), et `°C` ou `°F` pour les températures.
- **Quantités juxtaposées sans opérateur** <Since v="1.5.0" type="changed" /> : l'unité d'un ingrédient juxtapose deux quantités sans opérateur (`@farine{1 cup 5 tbsp}` ou `@farine{1 kg 200 g}`), sans quoi `cup 5 tbsp` passerait pour une seule unité inconnue sans masse. **Correction** : écrivez une [somme de quantités](/fr/docs/reference/syntax/ingredients/#sommes-de-quantités) (`@farine{1 kg + 200 g}`) ; `data.suggestion` fournit la forme corrigée pour les actions rapides de l'éditeur. Les mentions descriptives comme `@tomates{1 boîte de 400 g}` restent valides.
- **Mot avant le nombre** : une unité commence par un mot qui précède la quantité (`@farine{environ 200g}`), alors que toute quantité doit débuter par son nombre. **Correction** : écrivez `@farine{200g}` et laissez « environ » dans la phrase. Les quantités textuelles sans nombre (`{une pincée}`, `{au goût}`) sont acceptées.
- **Séparateur de Cooklang** <Since v="1.6.0" /> : un `%` entre le nombre et une unité de masse ou de volume (`@farine{200%g}`, `reason: "cooklangSeparator"`), qui passerait sinon pour une unité inconnue `%g`, sans masse. **Correction** : écrivez `@farine{200 g}` ; `data.suggestion` donne l'unité (`g`) et la correction rapide du serveur de langage remplace le `%` par une espace. Un `%` devant un autre mot (`{70 % cacao}`) ne déclenche rien.

### `INVALID_QUANTITY`
<Since v="1.5.0" />

Émis lorsqu'une [somme de quantités](/fr/docs/reference/syntax/ingredients/#sommes-de-quantités) ou une expression numérique ne peut pas être évaluée. La recette compile et s'affiche telle qu'écrite, mais la valeur est exclue de la liste de courses et de la nutrition. `data.reason` en précise la cause :

| `reason` | Exemple | Correction |
| :--- | :--- | :--- |
| `unitlessTerm` | `{1 + 1 tasse}` | Donnez son unité à chaque terme (`{1 tasse + 1 càs}`). |
| `percentTerm` | `{100 g + 10%}` | Écrivez le résultat (`{110 g}`, fourni dans `data.suggestion`) ou une quantité relative (`{10% &farine}`). |
| `expressionTerm` | `{2 x 100 g + 50 g}` | Les sommes n'acceptent que `+` et `-` ; écrivez `{250 g}`. |
| `quantityInUnit` | `{1 boîte de 400 g + 50 g}` | Exprimez la quantité dans une seule unité (`{450 g}`). |
| `nonPositiveTotal` | `{1 càs - 1 tasse}` | La quantité retirée atteint ou dépasse ce qui est ajouté. |
| `rangeAfterMinus` | `{1 tasse - 1-2 càs}` | Placez les fourchettes sur un terme ajouté, ou écrivez le total en fourchette. |
| `minusAcrossFamilies` | `{1 tasse - 20 g}` | Soustrayez uniquement au sein d'une même famille d'unités (volume d'un volume, masse d'une masse). |
| `zeroDenominator` | `{1/0 tasse}`, `{1/0% &pâte}`, `#poêle{1/0}`, `^{1/0 °C}` | Une division par zéro est ignorée ; écrivez une fraction valide (`1/2`). |
| `zeroRatioDenominator` | `{2 g / 0 g @&farine}`, `~{15 min / 0 g @&rôti}` | Une proportion rapportée à rien est ignorée ; indiquez la quantité de référence (`/ 100 g`). |
| `relativeNotSupported` | `@œufs{3}<@boîte{50% @&farine}`, `@œufs{1}<@boîte{1 / 100 g @&farine}` | Pourcentages et proportions ne sont pas encore pris en charge sur un parent composite ; indiquez sa quantité (`@œufs{3}<@boîte{1}`). |

La soustraction est vérifiée par famille d'unités : `{1 tasse - 2 càs + 30 g}` est valide (2 càs retirées de 1 tasse), tandis que `{1 tasse - 20 g}` n'a aucune masse dont soustraire les 20 g.

### `OZ_AFTER_VOLUME`
<Since v="1.5.0" />

Notice informative lorsqu'`oz` suit un volume dans une somme (`@eau{1 cup + 2 oz}`). Comme `oz` désigne une masse, Gram le garde séparé du volume. **Correction** : écrivez `fl oz` s'il s'agit d'onces liquides (`data.suggestion` propose cette correction rapide).

### `SPACED_COMPOSITE`
<Since v="1.5.2" />

Des espaces autour de l'opérateur composite (`@zeste de citron{1} < @citron{2}`, ou un espace d'un seul côté). Avec eux, la ligne se lit comme deux ingrédients distincts séparés par un `<` dans le texte : le citron s'achète en plus de l'entrée du zeste, soit deux citrons de trop sur la liste de courses. La recette compile quand même, telle qu'elle est écrite. **Correction** : collez `<` aux deux ingrédients (`@zeste de citron{1}<@citron{2}`) ; `data.suggestion` contient l'opérateur collé au parent (`<@citron`), que la correction rapide du serveur de langage écrit à la place de l'écart, et `gram format` fait la même réparation.

### `DURATION_OUT_OF_RANGE`

Un minuteur, ou le décalage du rétroplanning d'une section, dure plus de 1000 ans. **Correction** : vérifiez le nombre, souvent un chiffre en trop ou une lettre d'unité oubliée (`~{-3000d}` fait huit ans, `~{-3000000000d}` n'est plus une recette). La durée est ramenée à 1000 ans, pour que la chronologie reste finie au lieu de donner `0`, `Infinity` ou `NaN`. Cette limite est une borne technique, pas un jugement sur les recettes : tout ce qui la respecte, une solera de plusieurs décennies comprise, est planifié tel quel et ne déclenche rien.

### `AMBIGUOUS_NUMBER`
<Since v="1.5.0" />

Une virgule suivie de trois chiffres après un à trois chiffres entiers (`@farine{1,000 g}`, `@farine{12,500 g}`). Gram prenant en charge la virgule décimale sans séparateur de milliers, `{1,000 g}` est interprété comme `1 g` (et `{12,500 g}` comme `12,5 g`). Vérifié sur les quantités, minuteurs, températures, pourcentages et ancres de section (`@use` inclus). **Correction** : écrivez `{1000 g}` pour mille, ou `{1 g}` sinon. Un point (`{1.000 kg}`) reste toujours une décimale sans avertissement.

### `INVALID_DURATION`
<Since v="1.5.0" />

Un minuteur ou une ancre de section emploie des nombres et unités connus de Gram, mais sous une forme ambiguë ou non prise en charge :
- **Minuteurs ambigus ou invalides** : `~{1:30}` (heures ou minutes ?), `~{30min 1h}` (ordre inversé), `~{1h75}` (`≥ 60` après les heures), `~{1-2h30}` (borne ambiguë), `~{2-1 h}` (fourchette inversée), `~{2 * 2 min}` ou texte libre (`~{une demi-heure}`). Le minuteur est exclu du temps total tout en conservant son texte dans `raw`.
- **Ancres non prises en charge** : fourchettes (`~{-1-2j}`), secondes (`~{-1min30}`, `~{-5'}`) ou ancres proportionnelles (`reason: "anchorRatio"`).
- **Limites des temps proportionnels** : multiplicateurs (`~{15 min / 500 g @&rôti * 2}`, `reason: "ratioMultiplication"`) ou cibles en fourchette (`~{15 min / 1-2 kg @&rôti}`, `reason: "ratioShape"`).

**Correction** : suivez l'écriture suggérée dans `.message` (`~{1h30}`, `~{1:30 min}`, `~{1h30-2h}`). <Since v="1.6.0" /> Pour le séparateur de Cooklang (`~{15%min}`), `data.suggestion` donne la durée que Gram lit une fois le `%` remplacé par une espace (`15 min`), et la correction rapide du serveur de langage l'écrit entre les accolades. Un mot inconnu après un nombre lève toujours `INVALID_UNIT`, et un nombre seul `MISSING_UNIT`.

### `DEPRECATED_FRONTMATTER_KEY`

<Since v="1.6.0" /> Le frontmatter utilise une clé dépréciée, retirée en 2.0.0 : `servings` (écrivez `portions`), `yield` ou `yields` (écrivez `makes`). L'avertissement est levé même si la clé à écrire est aussi présente (c'est elle qui l'emporte). Il n'a pas de `loc` (l'AST ne garde pas la position des clés du frontmatter), mais porte `data: { key, suggestion }` : le serveur de langage le barre sur la clé et propose de la renommer, ou de retirer sa ligne si la clé à écrire est déjà là. Levé par un module importé, `data.specifier` le nomme et le diagnostic reste sur sa ligne `@use`. **Correction** : renommez la clé comme l'indique le message. Voir [Fonctionnalités dépréciées](/fr/docs/how-to/deprecations/).

### `SCOPE_CONFLICT`
Deux sections déclarent un même nom de variable (`->&nom`). Les noms de variables doivent être uniques à l'échelle de toute la recette, pas juste de la section. **Correction** : renommez l'une des deux variables.

### `MISSING_INGREDIENT`
Lors de l'estimation nutritionnelle, un ingrédient (dont on connaît la masse) n'a trouvé aucune correspondance (par ID ou alias) dans la base de données. **Correction** : ajoutez l'ingrédient ou son alias dans votre base.

### `MISSING_MACROS`
L'ingrédient a bien été trouvé en base, mais ne possède aucun bloc `nutrition`. **Correction** : documentez le bloc `nutrition` dans l'entrée YAML correspondante.

### `UNKNOWN_MASS`
L'Analyseur n'a pu résoudre aucune masse pour cet ingrédient (unité inexploitable, aucune densité/`unit_weight`), il est donc exclu des totaux nutritionnels. **Correction** : comme pour `RELATIVE_QUANTITY_UNKNOWN_MASS`, fournissez une unité standardisable ou des données physiques en base.

### `INVALID_MODIFIER_COMBINATION`
Modificateurs en conflit ou dupliqués sur un même ingrédient/matériel. Par exemple : `optional (?)` couplé à `important (*)`, ou `hidden (-)` avec `referenceable (&)`. La collision exacte est détaillée dans le `.message`. **Correction** : retirez le modificateur incriminé.

### `INVALID_BAKERS_REFERENCE`
L'ingrédient marqué comme ancre du % boulanger (via le modificateur `*` ou l'option `bakersReference`) possède lui-même une masse dérivée (quantité relative par rapport à un *autre* ingrédient). Il ne peut donc pas servir de base à 100 % (dépendance circulaire). **Correction** : choisissez un ingrédient doté d'une quantité absolue pour servir de point de référence.

### `NO_BAKERS_REFERENCE`
Le mode *Baker's Math* a été explicitement requis (via `enableBakersMath` avec un modificateur `*` nu, ou via un identifiant `bakersReference`), mais aucun ingrédient correspondant n'a été trouvé. **Correction** : ajoutez le modificateur `*` sur un ingrédient, ou corrigez l'ID passé à `bakersReference`.

### `MULTIPLE_BAKERS_PERCENTAGE`
<Since v="1.5.1" /> Plusieurs ingrédients sont marqués comme base des pourcentages du boulanger (`@*farine{500 g}` et `@*seigle{100 g}`). Le premier marqué reste la base, les autres perdent leur `*`, et le reste de la recette se compile normalement. Le même ingrédient marqué deux fois reste une seule base : rien n'est signalé. **Correction** : ne gardez le `*` que sur un seul ingrédient.

### `COMPOSITE_PARENT_CONFLICT`

Un nom court d'ingrédient composite (ex : `@jus`) est extrait de deux parents différents dans la même recette (ex : `<@citron` dans une étape et `<@orange` dans une autre). **Correction** : utilisez le nom complet de l'enfant (ex : `@jus de citron` et `@jus d'orange`) pour éviter les collisions d'identité dans la base de données.

### `MODULE_NOT_FOUND`

Un module importé via une directive `@use` n'a pas pu être résolu ou trouvé sur le système de fichiers. **Correction** : vérifiez le chemin du fichier, l'extension (`.gram`) ou les alias configurés dans `config.yaml`.

### `DAY_OVERFLOW`

Une journée de travail (définie par l'ancre `~{-Nd}` d'une section) débute avant l'ouverture de sa fenêtre de 24 heures en raison d'un temps de repos passif prolongé. **Correction** : ancrez la section un jour plus tôt (par exemple `~{-2d}` au lieu de `~{-1d}`), ou réduisez la durée du repos.

### `TIME_PARADOX`

Lors de la planification inverse ALAP, une tâche de production est tirée avant l'instant initial de la recette pour honorer l'échéance de consommation d'un intermédiaire ou le service. Gram translate l'ensemble de la chronologie pour la faire débuter à zéro. **Correction** : vérifiez que les étapes actives et les temps de repos prévus laissent un délai réaliste avant l'échéance.

### `TRACK_CONTENTION`

Plusieurs minuteurs passifs partagent la même piste d'équipement matériel (ex. `~_four`) et ne peuvent pas se dérouler en simultané. L'ordonnanceur les sérialise l'un après l'autre pour éviter toute collision matérielle, retardant la seconde tâche. **Correction** : il s'agit d'une notification informative ; si vous disposez de plusieurs équipements distincts, assignez-leur des noms de pistes différenciés (ex. `~_four1` et `~_four2`).

### `PASSIVE_OVERLAP_SAME_COOKWARE`

Deux minuteurs passifs se recouvrent dans le temps, dans des étapes qui citent le même ustensile (`#four` dans les deux), sans piste nommée commune. Si l'un doit suivre l'autre, ils sont probablement dans un seul four : le plan les montre côte à côte. **Correction** : donnez-leur la même piste nommée (`~_four{30min}` puis `~_four{20min}`) pour qu'ils passent à tour de rôle ; si les deux tiennent dans le four en même temps, ce n'est qu'une information. Seuls les noms sont comparés (`#four` avec `#four`), donc cela marche quelle que soit la langue de la recette, et le recouvrement est lu sur la chronologie par défaut.

### `MODULE_PARSE_ERROR`

Un module importé par `@use` ne se lit pas : aucune de ses sections ne peut être insérée. Sur le document vérifié lui-même, le message est celui du parser. **Correction** : ouvrez le fichier importé et corrigez l'erreur de syntaxe que cite le message.

### `MODULE_CYCLE`

Deux modules ou plus s'importent l'un l'autre, directement ou par d'autres (`a.gram` importe `b.gram`, qui importe `a.gram`). Le message donne la chaîne complète. **Correction** : placez ce dont ils ont tous deux besoin dans un troisième module, qui n'importe aucun des deux.

### `MODULE_DEPTH_EXCEEDED`

La chaîne d'imports est plus profonde que ce que Gram accepte de suivre. **Correction** : raccourcissez-la en important la base directement depuis la recette qui en a besoin.

### `MODULE_EXPORT_NOT_FOUND`

Une liaison de `@use` demande un nom que le module n'exporte pas (`as &sauce` alors que ses sections exportent `&base`). Seul un `->&nom` posé sur un en-tête de section est exporté : si le nom existe dans le module comme `->&` d'étape, le message précise qu'il n'est pas réexporté, et le serveur de langage propose d'ajouter `->&nom` à l'en-tête de la section qui le déclare, dans le module. Sinon, il suggère l'export le plus proche. **Correction** : utilisez l'un des exports listés, ou exportez le nom depuis le module.

### `UNUSED_IMPORT`

Une liaison de `@use` n'est jamais utilisée dans la recette. **Correction** : utilisez-la (`&nom`) ou retirez-la de la ligne `@use`.

### `UNRESOLVED_MODULE_YIELD`

La recette demande une quantité d'un intermédiaire importé (`&pate{300 g}`), mais le rendement du module ne se pèse pas : l'un de ses ingrédients n'a pas de masse connue. Le module ne peut donc pas être mis à l'échelle de la quantité demandée. **Correction** : donnez une masse à cet ingrédient, ou une densité ou un poids unitaire dans la base d'ingrédients.

### `ESTIMATED_MODULE_YIELD`

Le rendement du module a été pesé avec des densités ou des poids unitaires standards : le facteur d'échelle qui lui est appliqué reste une estimation. **Correction** : écrivez les ingrédients du module en grammes pour un facteur exact, ou acceptez l'estimation.

### `MODULE_UNIT_MISMATCH`

La recette demande un intermédiaire importé dans une unité vers laquelle le rendement du module ne se convertit pas (un volume pour un rendement en grammes, sans densité). **Correction** : demandez-le dans l'unité de son rendement, ou donnez une densité au module.

### `MODULE_BATCH_INTERPRETATION`

Un intermédiaire importé est demandé avec un nombre sans unité (`&pate{2}`) : il est lu comme autant de fournées du module. **Correction** : simple information ; écrivez une unité pour demander une quantité.

### `IMPORTED_BAKERS_REFERENCE_DROPPED`

Le module désigne une base de pourcentage du boulanger (`@*farine`), qui reste propre au module : la recette qui l'importe n'en hérite pas. **Correction** : simple information ; désignez une base dans la recette importatrice si elle en a besoin.

### `DENSITY_OVERRIDE_SHADOWED`

La recette importatrice et le module surchargent tous deux la densité du même ingrédient (`densities:`), avec des valeurs différentes : celle de la recette importatrice l'emporte. **Correction** : simple information ; gardez une seule valeur si l'écart n'est pas voulu.

### `MODULE_SURPLUS`

Plusieurs liaisons d'un même `@use` sont demandées dans des quantités qui ne respectent pas les proportions du module : il est mis à l'échelle pour celle qui en demande le plus, et une autre en sort plus abondante que ce que la recette utilise. Le message donne l'excédent. **Correction** : simple information ; ajustez les quantités si l'excédent n'est pas voulu.

### `MODULE_SPECIFIER_INVALID`

Le chemin d'un `@use` a une forme que Gram ne lit pas : un chemin absolu (`/home/…`, non portable), un chemin `hub:` (pas encore pris en charge), un chemin qui ne commence ni par `./`, ni par `../`, ni par `@…/`, ou qui ne finit pas par `.gram`. Le message en donne la raison. **Correction** : écrivez un chemin relatif, `@/…` depuis la racine du projet, ou `@alias/…` avec un alias déclaré sous `paths:` dans `.gram/config.yaml`.

### `MODULE_SCHEME_UNSUPPORTED`

Le chemin d'un `@use` est une URL (`https://…`, ou tout autre `schéma://`) : les modules se lisent uniquement dans le projet. **Correction** : copiez le module dans le projet et importez-le par son chemin.

### `STOCKED_RETRO_PLANNING_IGNORED`

Un module importé en stock (`--stock`) porte un décalage de rétro-planning (`~{-1d}`) : un élément en stock est déjà prêt, le décalage est donc ignoré. **Correction** : retirez le décalage, ou importez le module sans `--stock` pour planifier sa préparation.

### `RETRO_PLANNING_OVERRIDE_SHADOWED`

La ligne `@use` fixe un décalage de rétro-planning qui remplace celui que le module fixe lui-même. **Correction** : simple information ; gardez-en un seul si l'écart n'est pas voulu.

### `MODULE_BINDING_SHADOWS_INGREDIENT`

Le nom local d'un intermédiaire importé est aussi celui d'un ingrédient de la base (`as &beurre`) : les deux se confondent facilement dans la nutrition et la liste de courses. **Correction** : donnez un autre nom local à la liaison (`as &beurre_noisette`).

### `STOCKED_DESTRUCTURED_NUTRITION_BLENDED`

Un module en stock est importé avec plusieurs liaisons (`as { &a, &b }`) : sa nutrition n'est connue que pour le module entier, chaque liaison reçoit donc son profil moyen. **Correction** : simple information ; découpez le module si chaque partie doit avoir sa propre nutrition.

## Codes de la couche de lint

<Since v="1.6.0" /> Le serveur de langage tire ses diagnostics de `@gram-lang/modules/lint` (expérimental, voir l'[API Modules](/fr/docs/reference/api/modules/#lint)) : on y retrouve les avertissements du compilateur ci-dessus, plus des vérifications propres, faites sur le texte source plutôt que sur la recette compilée. Leur sévérité peut aussi valoir `hint`, qui ne fait jamais échouer un build, même sous `--strict`. Chaque diagnostic renvoie vers sa section de cette page.

### `PARSE_ERROR`

Le document ne se lit pas : le message est celui du parser, à l'endroit où il s'est arrêté. Aucun autre diagnostic n'apparaît tant que l'erreur reste. **Correction** : corrigez la syntaxe à l'endroit indiqué.

### `COMPILE_ERROR`

Le document se lit, mais sa compilation ou son analyse a échoué (une mise à l'échelle impossible, par exemple). Le diagnostic s'affiche en tête de fichier. **Correction** : corrigez ce que nomme le message.

### `MISSING_TITLE`

Le frontmatter n'a pas de `title:` (ou le fichier n'a pas de frontmatter). Les vues se rabattent alors sur un titre générique. Si le fichier ouvre un frontmatter, le serveur de langage propose d'ajouter la clé. **Correction** : ajoutez `title: …` au frontmatter.

### `UNUSED_INTERMEDIATE`

Une étape déclare un intermédiaire (`->&sauce`) qu'aucune étape n'utilise, ni comme référence (`&sauce`), ni comme cible d'une part, d'un ratio ou d'un minuteur proportionnel (`@sel{2% &sauce}`). Celui d'un en-tête de section n'est jamais signalé : c'est ce qu'exporte un module, ou le nom du plat fini. Le serveur de langage propose de le retirer. **Correction** : utilisez-le, ou retirez le `->&`.

### `UNKNOWN_INGREDIENT`

Un ingrédient est introuvable dans la base d'ingrédients, résolu comme le fait la nutrition (son nom, ses alias, le même slug). La vérification n'a lieu que si une base est chargée. Le serveur de langage propose le nom le plus proche de la base (le premier, si plusieurs le sont autant), jamais comme correctif préféré : renommer un ingrédient change la recette, donc ni la correction automatique d'un éditeur ni `gram check --fix` ne l'appliquent. Un second correctif, jamais préféré, ajoute l'ingrédient à la base que lit l'éditeur (le fichier indiqué par `database:` dans `.gram/config.yaml`, sinon `.gram/ingredients.yaml`) : une entrée avec son `name` et, en commentaire, le squelette des champs à remplir (alias, catégorie, allergènes et régimes dans `tags`, densité, poids unitaire, valeurs nutritionnelles pour 100 g). Il n'est pas proposé si la base a déjà une entrée à ce nom. **Correction** : corrigez l'orthographe, ou ajoutez l'ingrédient à la base (un pluriel se déclare dans ses `aliases`).

### `LOST_INGREDIENT`

Un ingrédient est écrit mais jamais lu : un `//` placé plus tôt sur la même ligne a changé la fin de celle-ci en commentaire. Avec `Mélanger @farine{200 g} // selon le goût, @sel{}`, pas de sel, ni dans la liste de courses ni ailleurs. Seul compte un `//` au milieu d'une étape : une ligne `//` entière et un bloc `/* … */` sont des commentaires voulus. Aucun correctif n'est proposé, car seul l'auteur sait si l'erreur vient du commentaire ou de l'ingrédient. **Correction** : mettez le commentaire sur sa propre ligne, ou terminez-le avant l'ingrédient.

### `MERGED_STEP_LINE`

Une ligne censée ouvrir un nouveau bloc est lue comme la suite de l'étape du dessus, parce qu'un simple saut de ligne ne termine pas une étape : une ligne qui commence par `[Action]` (l'action de l'étape suivante), une ligne `## …` (la section disparaît), ou toute ligne qui suit une ligne terminée par `->&nom` (la sortie de l'étape, après laquelle on voulait sans doute une autre étape). Un saut de ligne ordinaire au sein d'une étape reste valable (`Une étape,` puis `la même étape.` à la ligne), et une ligne qui ne pourrait pas ouvrir un bloc à elle seule n'est pas signalée (une action `[Action]` sans rien derrière, un `## …` suivi de texte après son `~{…}`) : une ligne vide n'en ferait qu'une erreur de syntaxe. Le serveur de langage propose d'insérer la ligne vide, en correctif préféré. **Correction** : laissez une ligne vide avant la ligne signalée.

### `SUSPECT_INGREDIENT_NAME`

Le nom d'un ingrédient écrit avec accolades ressemble à une phrase : il contient `, `, `; `, `. ` (après un mot d'au moins quatre lettres, pour épargner `St. John's wort`), `、` ou `。`, ou dépasse 6 mots ou 40 caractères. Ce n'est qu'une indication : `@chocolat noir 70 %, en pistoles{200 g}` est un nom valide, mais `en pistoles` a sans doute sa place dans la préparation. Quand une ponctuation coupe le nom, le serveur de langage propose, sans jamais le mettre en avant, d'en passer la fin entre parenthèses : `@chocolat noir 70 %{200 g}(en pistoles)`. **Correction** : gardez un nom court, et le reste dans la préparation.

### `UNREAD_FRONTMATTER`

Le fichier ouvre un bloc `---` avec des clés, mais la recette n'a aucune métadonnée : une ligne que le frontmatter n'accepte pas, un commentaire `# …` ou une ligne indentée (`  - flour: 0.55`), a fait de tout le bloc le texte d'une étape, titre compris. Le diagnostic s'affiche sur cette ligne ; `MISSING_TITLE` n'est alors pas signalé si le bloc écrit un `title:`. Sur une ligne `# …`, le serveur de langage propose de la retirer (sans la mettre en avant) ; jamais sur une ligne indentée, qui porte des données. **Correction** : retirez le commentaire, et écrivez les listes en ligne (`densities: [flour:0.55, milk:1.03]`).

## Configurer le lint

<Since v="1.6.0" /> Un projet règle les vérifications de l'éditeur et de [`gram check`](/fr/docs/reference/tooling/cli/#gram-check-motif) dans `.gram/config.yaml` : un code peut être coupé, ou affiché avec une autre sévérité (`hint`, `info` ou `warning`). Une erreur (`error`) ne se coupe ni ne s'abaisse jamais, pour qu'une recette cassée ne puisse pas passer inaperçue.

```yaml
lint:
  rules:
    UNKNOWN_INGREDIENT: off
    UNUSED_INTERMEDIATE: hint
```

Pour un seul bloc, un commentaire `// gram-ignore` sur une ligne à part, suivi d'un ou plusieurs codes, suffit :

```gram
## Sauce

// gram-ignore UNUSED_INTERMEDIATE
Faire réduire @bouillon{200 ml}. ->&reduction
```

Le commentaire vaut pour le bloc qui le suit : une étape entière, sur autant de lignes qu'elle en compte, ou la ligne d'un en-tête de section (pas les étapes qui suivent). Plusieurs lignes `// gram-ignore` d'affilée se cumulent ; un `// gram-ignore` seul, sans code, n'a aucun effet. Les diagnostics hors étape et hors en-tête (frontmatter, lignes `@use`, diagnostics en tête de fichier) n'en acceptent pas, car on ne peut pas y écrire de commentaire sans changer le sens du fichier : ils se règlent dans `.gram/config.yaml`. N'écrivez jamais `// gram-ignore` en fin de ligne d'une étape : à cet endroit, `//` transforme la fin de la ligne en commentaire.
