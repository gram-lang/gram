Gram fonctionne dans tout éditeur qui parle le Language Server Protocol, avec deux niveaux de prise en charge.

## Deux niveaux de prise en charge

- **Support officiel** : [VS Code et ses dérivés](#vs-code-et-ses-dérivés), avec l'extension publiée sur le VS Code Marketplace et sur Open VSX. Une extension pour Zed viendra s'y ajouter. Ces intégrations sont maintenues et vérifiées par le projet.
- **Configurations LSP communautaires** : [Neovim](#neovim), [Helix](#helix), [Emacs](#emacs), [Sublime Text](#sublime-text) et les [IDE JetBrains](#ide-jetbrains). Elles ne reposent que sur le protocole standard : l'éditeur lance `gram-language-server --stdio` et envoie `views: false`. Chacune est une base qui fonctionne, d'où partir, sans maintenance propre à chaque éditeur. Retours et pull requests de celles et ceux qui utilisent ces éditeurs sont les bienvenus, sur le [suivi des tickets](https://git.gram-lang.org/gram-lang/gram/issues) ou directement dans le dossier `editors/` du dépôt.

Les configurations communautaires ne sont pas toutes vérifiées de la même façon :

- chacune passe un test de contrat à chaque modification (`editors.test.ts` : la commande, `views: false`, l'extension `.gram` et les commentaires), et le serveur lui-même est testé tel que le voit n'importe quel client LSP ;
- **Neovim et Emacs** sont en plus pilotés par leur propre client LSP dans un conteneur (`editors/smoke/run.sh` : diagnostics, complétion, survol, formatage, renommage), et **Helix** y vérifie qu'il lit la configuration et trouve le serveur ;
- **Sublime Text et les IDE JetBrains** sont fournis tels quels, sans banc d'essai dans l'éditeur lui-même. Leurs écrans de réglages changent d'une version à l'autre : c'est leur propre documentation qui fait foi pour l'emplacement de chaque champ.

## Ce que chaque éditeur sait faire

| Éditeur | Prise en charge | Coloration | Diagnostics | Complétion | Survol | Formatage | Renommage | Aperçu |
|---|---|---|---|---|---|---|---|---|
| [VS Code et ses dérivés](#vs-code-et-ses-dérivés) | Officielle | Complète (grammaire TextMate et jetons sémantiques) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| [Neovim](#neovim) | Communautaire, testée en conteneur | Partielle (jetons sémantiques) | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [Helix](#helix) | Communautaire, configuration vérifiée en conteneur | Pas encore | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [Emacs](#emacs) | Communautaire, testée en conteneur | Commentaires seulement | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [Sublime Text](#sublime-text) | Communautaire, telle quelle | Complète (grammaire TextMate) | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| [IDE JetBrains](#ide-jetbrains) | Communautaire, telle quelle | Partielle (jetons sémantiques), complète avec le bundle TextMate | ✓ | ✓ | ✓ | ✓ | ✓ | — |

Les colonnes de fonctionnalités disent ce que le serveur envoie ; pour Sublime Text et les IDE JetBrains, elles ne sont pas vérifiées dans l'éditeur.

- **La coloration partielle** vient des jetons sémantiques du serveur : sigles et noms (`@farine`, `#bol`, `&pâte`), accolades, modificateurs, actions et commentaires prennent une couleur, mais pas le contenu des accolades (quantités, durées, températures). Elle attend aussi la réponse du serveur, un instant après l'ouverture du fichier.
- **L'aperçu** de la recette et du <Term id="runSheet" /> n'existe pour l'instant que dans VS Code.

## Support officiel

### VS Code et ses dérivés

Installez l'extension **Gram - Recipe Language** depuis le [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=gram-lang.gram-lang), ou depuis [Open VSX](https://open-vsx.org/extension/gram-lang/gram-lang) pour VSCodium, Cursor, Windsurf ou Positron. Elle embarque le serveur : rien d'autre à installer. Voir [Extension VS Code](/fr/docs/reference/tooling/vscode-extension/).

## Configurations LSP communautaires

Ces configurations sont des points de départ : adaptez-les à votre installation, et partagez ce que vous améliorez.

### Installer le serveur

Chaque éditeur ci-dessous lance le serveur comme une commande. Installez-le une fois pour toutes :

```bash
npm install -g @gram-lang/language-server
```

Ces configurations lancent `gram-language-server --stdio`. Si la CLI est déjà installée, `gram lsp` lance le même serveur : remplacez la commande par celle-ci si vous préférez.

Toutes envoient aussi `views: false` : ces éditeurs n'ont pas de panneau d'aperçu, le serveur ne calcule donc aucune vue et s'en tient aux fonctionnalités standard du LSP.

Un éditeur lancé depuis un menu ne voit pas toujours le `PATH` de votre terminal. S'il ne trouve pas `gram-language-server`, donnez-lui le chemin complet qu'affiche `which gram-language-server` (`where gram-language-server` sous Windows).

- La complétion est celle de Neovim : <kbd>Ctrl</kbd>+<kbd>x</kbd> <kbd>Ctrl</kbd>+<kbd>o</kbd>, puis <kbd>Ctrl</kbd>+<kbd>y</kbd> pour valider. Un ingrédient au nom de plusieurs mots arrive avec ses accolades, le curseur entre les deux (`@Farine de blé{}`).

Testé avec Neovim 0.11.6 et 0.12.6.

### Sublime Text

Fourni tel quel, sans test dans l'éditeur. Il faut trois choses à Sublime Text : la syntaxe Gram, les réglages de commentaires et le paquet [LSP](https://packagecontrol.io/packages/LSP).

### IDE JetBrains

Fourni tel quel, sans test dans l'IDE. IntelliJ IDEA, WebStorm, PyCharm et les autres IDE JetBrains peuvent faire tourner le serveur grâce au plugin [LSP4IJ](https://plugins.jetbrains.com/plugin/23257-lsp4ij).
