Le formateur canonique des fichiers `.gram`. Il sert la commande `gram format` du CLI, le formatage du serveur de langage (et donc de l'extension VS Code), et la sortie de l'importeur IA. Chaque règle ne touche que des espaces ou des graphies, jamais le sens d'une recette, et le relancer une seconde fois ne change plus rien.

## API

```typescript
function formatGram(source: string): { content: string; changes: FormatterChanges }
function hasChanges(changes: FormatterChanges): boolean
function summarizeChanges(changes: FormatterChanges): string

interface FormatterChanges {
  lowercasedIds: number;
  spacesBeforeBrace: number;
  spacesInsideBraces: number;
  trailingZeros: number;
  quantityOperatorSpacing: number; // depuis la 1.5.0
  temperatureSpacing: number;
  compositeSeparatorSpacing: number;
  arrowDeclarationSpacing: number;
  headerSpacing: number;
  tabsToSpaces: number;
  consecutiveBlankLines: number;
  trailingWhitespace: number;
  eofNewline: boolean;
}
```

`formatGram` renvoie la source formatée et le nombre de modifications par règle. `hasChanges` indique si quelque chose a changé (ce sur quoi s'appuie `gram format --check`), et `summarizeChanges` écrit ces comptes sur une ligne (`2 trailing zeros removed · 2 sums spacing fixed`).

## Règles de formatage

Les règles 1 à 9 ne s'appliquent qu'au corps de la recette : le frontmatter est du YAML brut, laissé tel quel. Les règles 10 à 12 s'appliquent à tout le fichier.

<CardGrid>
  <Card title="Quantités" icon="star">
    - **1. Identifiants en minuscules** (`lowercasedIds`) : `@Flour` → `@flour`.
    - **2. Pas d’espace avant une accolade** (`spacesBeforeBrace`) : `@flour {200g}` → `@flour{200g}`.
    - **3. Pas d’espace dans les accolades** (`spacesInsideBraces`) : `{ 200g }` → `{200g}`.
    - **4. Zéros superflus** (`trailingZeros`) : `{500.0g}` → `{500g}`, `{1,50 kg}` → `{1,5 kg}`. `{1,000 g}` reste tel qu’écrit : le compilateur le signale (`AMBIGUOUS_NUMBER`).
    - **4b. Sommes de quantités** <Since v="1.5.0" /> (`quantityOperatorSpacing`) : une espace autour de chaque `+` ou `-` d’une somme, et la règle 4 terme par terme (`{1.50 cup+2.0 tbsp}` → `{1.5 cup + 2 tbsp}`).
  </Card>
  <Card title="Autres jetons" icon="list-format">
    - **5. Températures** (`temperatureSpacing`) : `^{180 °C}` → `^{180°C}`.
    - **6. Composites** (`compositeSeparatorSpacing`) : `@juice{} < @lemon{}` → `@juice{}<@lemon{}`.
    - **7. Déclarations** (`arrowDeclarationSpacing`) : `->&batter {}` → `->&batter{}`.
    - **8. Titres de section** (`headerSpacing`) : `##Batter` → `## Batter`.
    - **9. Tabulations** (`tabsToSpaces`) : une tabulation devient quatre espaces.
  </Card>
  <Card title="Tout le fichier" icon="document">
    - **10. Espaces de fin de ligne** (`trailingWhitespace`) : les espaces et les tabulations qui terminent une ligne, et rien d’autre, puisque le parser ne tient aucun autre caractère pour un blanc (une espace insécable reste en place). Tous les sauts de ligne (CRLF, ou un CR isolé) deviennent des LF.
    - **11. Lignes vides** (`consecutiveBlankLines`) : deux lignes vides ou plus n’en font plus qu’une. Une ligne vide manquante n’est jamais ajoutée : entre deux lignes, elle couperait une étape en deux.
    - **12. Saut de ligne final** (`eofNewline`) : une fois les lignes vides de la fin retirées, le fichier se termine par un seul LF. Une marque d’ordre des octets (BOM) en tête de fichier reste en place.
  </Card>
</CardGrid>

### Sommes de quantités

<Since v="1.5.0" />

La règle 4b ne touche que les accolades d'un ingrédient, d'un parent composite ou d'une référence (`@…{`, `<@…{`, `&…{`), jamais celles d'un minuteur ni d'une température : `~{1h30-2h}` reste tel qu'écrit. Un `-` ne reçoit ses espaces qu'après une unité, pour qu'une fourchette reste une fourchette : `{1 cup-2 tbsp}` devient `{1 cup - 2 tbsp}`, mais `{1-2 cups}` ne bouge pas. Un `+` ne reçoit ses espaces que devant un nombre (`{sel+poivre}` ne bouge pas). Hors d'une somme, la règle 4 garde sa portée : `{1.50 cup}` reste tel qu'écrit.
