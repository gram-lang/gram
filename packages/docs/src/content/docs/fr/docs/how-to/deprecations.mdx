Cette page répertorie l'ensemble des éléments dépréciés dans Gram, organisés selon leur version majeure de suppression cible. **Une fonctionnalité dépréciée demeure pleinement opérationnelle et préserve son comportement nominal jusqu'à la version indiquée**. Chaque élément dispose d'une alternative moderne accessible immédiatement, facilitant une migration progressive sans rupture brutale.

## Êtes-vous concerné ?

| Profil d'utilisation | Actions à prévoir |
|---|---|
| Rédaction de recettes `.gram` via le CLI, le moteur de rendu ou le playground | **Aucune**. La syntaxe du langage ne comporte aucune dépréciation. |
| Consommation du JSON compilé (`gram build`, interface web personnalisée, scripts) | Consultez les sections [Champs du JSON compilé](#champs-du-json-compilé) et [Compatibilité avec les versions antérieures](#compatibilité-avec-les-versions-antérieures). |
| Intégration programmatique de `@gram-lang/kitchen` ou `@gram-lang/analyzer` | Consultez [Champs du JSON compilé](#champs-du-json-compilé), [`calculatePreparationTime`](#la-fonction-calculatepreparationtime) et [Compatibilité avec les versions antérieures](#compatibilité-avec-les-versions-antérieures). |

Pour vérifier l'état de votre code applicatif, reportez-vous à la section [Identifier les usages dépréciés dans votre code](#identifier-les-usages-dépréciés-dans-votre-code).

## Suppressions programmées en version 2.0.0

### Champs du JSON compilé

<Since v="1.4.0" type="deprecated" />

Depuis la version 1.4.0, l'objet recette compilé expose `miseEnPlace` (coût estimé de préparation par section), `tasks` (graphe de tâches neutre décrivant les actions et leurs dépendances) et `schedule` (ordonnancement par défaut calculé à partir de ce graphe : mise en place par section, durées passives au plus court).

Tout ordonnancement alternatif (mise en place groupée au départ, par journée de travail, ou durées passives maximales) est calculé à la volée via `layout(recipe.tasks, options)` ou `scheduleFor(recipe, mode, rests)`, sans nécessiter de recompilation. Ces nouvelles propriétés remplacent les champs historiques suivants :

| Champ déprécié | Propriété de remplacement |
|---|---|
| [`steps[].timings`](#horodatage-des-étapes-et-tâches-passives) | Blocs de type `step` dans `schedule.blocks` |
| [`steps[].backgroundTasks`](#horodatage-des-étapes-et-tâches-passives) | Blocs de type `passive` dans `schedule.blocks` |
| `metrics.totalTime` | `schedule.totalTime` |
| `metrics.idleTime` | `schedule.idleTime` |
| `metrics.activeTime` | `schedule.activeTime` |
| [`metrics.activeBreakdown`, `metrics.prepBreakdown`, `metrics.totalBreakdown`](#ventilation-détaillée-des-durées) | Propriétés structurées `miseEnPlace` et `schedule` |

:::note[Maintien de metrics.preparationTime]
La métrique `metrics.preparationTime` n'est **pas** dépréciée : sa valeur demeure invariante quelle que soit la stratégie d'ordonnancement choisie.
:::

`metrics.activeTime` évaluait un minuteur actif exprimé en fourchette (`~{20-25min}`) à sa valeur moyenne, conformément au comportement historique. À l'inverse, `schedule.activeTime` le planifie sur sa borne maximale pour garantir la ponctualité du service. Les deux valeurs sont strictement identiques pour une recette ne comportant aucune fourchette.

L'ancienne métrique `metrics.totalTime` calculait le temps total en supposant une préparation initiale groupée. Par défaut, les outils de Gram appliquent désormais la stratégie `perSection` : utilisez `scheduleFor(recipe, 'upfront')` pour obtenir une valeur comparable à l'ancien comportement. Le résultat sera identique, sauf si la recette fait intervenir des ingrédients intermédiaires (lesquels ne sont mobilisés en mode `upfront` qu'une fois produits).

### Horodatage des étapes et tâches passives

Auparavant, chaque étape encapsulait son propre calendrier d'exécution et ses tâches d'attente :

```typescript
for (const section of recipe.sections) {
  for (const step of section.steps) {
    if (step.type !== 'step') continue; // les commentaires n'ont pas d'horodatage
    draw(step.action, step.timings.start, step.timings.end);
    for (const task of step.backgroundTasks) {
      const start = step.timings.start + task.startOffset;
      draw(task.name ?? 'Timer', start, start + task.duration);
    }
  }
}
```

Désormais, exploitez les blocs de l'ordonnancement retenu. Toutes les durées sont exprimées en minutes relatives depuis 0 et intègrent la mise en place : elles dépendent de la stratégie d'ordonnancement choisie et ne doivent pas être combinées avec l'ancien champ `timings` au sein d'un même graphique.

```typescript
import { scheduleFor } from '@gram-lang/kitchen';

const schedule = scheduleFor(recipe, chosenMode); // 'perSection', 'upfront' ou 'perSession'

for (const block of schedule.blocks) {
  if (block.kind === 'prep') continue; // mise en place de section (nouveau type de bloc)
  const step = recipe.sections[block.section].steps[block.step];
  const label = block.kind === 'passive' ? (block.track ?? 'Timer') : step.action;
  draw(label, block.start, block.end);
}
```

Le guide [Créer une UI personnalisée](/fr/docs/how-to/build-custom-ui) présente un exemple d'intégration complet.

### Ventilation détaillée des durées

Les champs `metrics.activeBreakdown`, `metrics.prepBreakdown` et `metrics.totalBreakdown` fournissaient des listes de durées étiquetées. Ces informations sont désormais accessibles directement dans les structures de données sources :

- **Détail de la préparation** : inspectez les éléments `items` de chaque section dans `miseEnPlace` ;
- **Chronologie des étapes** : inspectez les blocs de `schedule.blocks` (la durée d'un bloc s'obtient par `end - start`).

### La fonction `calculatePreparationTime`

<Since v="1.4.0" type="deprecated" />

**Élément déprécié :** la propriété `breakdown` du résultat. **Remplacement recommandé :** les éléments de `computeMiseEnPlace`.

La fonction `calculatePreparationTime(sections, registry)` de `@gram-lang/kitchen` renvoie un objet `{ total, breakdown }`. Le tableau `breakdown` contient des libellés textuels composites (`ingredients_overhead`, `cookware_overhead`, `prep_<id>`). Ce champ sera supprimé avec la version 2.0.0, la fonction renvoyant alors uniquement `{ total }`. Le code lisant déjà `total` restera inchangé.

Avant :

```typescript
const { total, breakdown } = calculatePreparationTime(sections, registry);
for (const item of breakdown) show(item.label, item.duration);
```

Désormais, lisez les éléments structurés de la mise en place :

```typescript
import { calculatePreparationTime, computeMiseEnPlace } from '@gram-lang/kitchen';

const { total } = calculatePreparationTime(sections, registry);
for (const entry of computeMiseEnPlace(sections, registry)) {
  for (const item of entry.items) {
    // { kind: 'gather', target: 'ingredient' | 'cookware', count, duration }
    // { kind: 'prepare', ref: { type, id }, duration }
    show(item, item.duration);
  }
}
```

Une recette compilée porte déjà cette décomposition au sein de son champ `miseEnPlace`.

### Compatibilité avec les versions antérieures

<Since v="1.4.0" type="deprecated" />

**Élément déprécié :** le repli automatique sur les anciens champs `metrics`. **Solution de remplacement :** recompiler vos recettes avec `@gram-lang/kitchen` ≥ 1.4.0.

Le JSON produit par Kitchen 1.3.0 ou antérieur ne comporte ni `tasks` ni `schedule`. Jusqu'à la version 2.0.0, `scheduleTimes(compiled, mode, rests)` lit encore les durées dans les anciens champs `metrics` en mode dégradé. Ce mécanisme de compatibilité transitoire sera retiré en version 2.0.0.

Pour distinguer les deux formats, examinez la métadonnée `generator` : une recette compilée avec Kitchen ≥ 1.4.0 mentionne le compilateur d'origine (`"@gram-lang/kitchen@1.4.0"`), tandis qu'un export antérieur est dépourvu de ce champ. Recompilez vos recettes archivées avant d'adopter la future version 2.0.0.

## Identifier les usages dépréciés dans votre code

Vous pouvez rechercher les identifiants dépréciés au sein de votre base de code. La déstructuration d'objets (`const { totalTime } = recipe.metrics`) est également ciblée par cette commande :

```bash
grep -rnE "\b(timings|backgroundTasks|totalTime|idleTime|activeTime|activeBreakdown|prepBreakdown|totalBreakdown|calculatePreparationTime)\b" src/
```

Si vous développez en TypeScript, les champs et fonctions dépréciés de `@gram-lang/kitchen` sont signalés visuellement (texte barré) dans votre environnement avec l'alternative recommandée affichée dans l'infobulle.
