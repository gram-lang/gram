Si vous construisez une application web moderne (avec React, Vue, Svelte ou Next.js, par exemple), vous avez tout intérêt à consommer directement le **JSON** compilé par Gram et à le *mapper* sur vos propres composants d'interface utilisateur (UI).

Bien que le *parser* produise d'abord un Arbre Syntaxique Abstrait (AST) brut, les *packages* `@gram-lang/kitchen` et `@gram-lang/analyzer` transforment cet AST en un JSON hyper-structuré, prêt à l'emploi. Ce guide vous montre comment l'extraire programmatiquement et comment il est architecturé, afin que vous puissiez l'exploiter librement.

1. ### Récupérer le JSON
   
   Gram est conçu pour s'exécuter n'importe où (Node.js, environnements Edge ou directement dans le navigateur). Pour récupérer le JSON intégralement enrichi d'une recette, vous devez combiner ses trois *packages* fondamentaux :
   
   ```typescript
   import { getAST } from '@gram-lang/parser';
   import { compile } from '@gram-lang/kitchen';
   import { analyze } from '@gram-lang/analyzer';
   
   function getRecipeData(sourceCode: string) {
     // 1. Parser le texte en arbre syntaxique
     const ast = getAST(sourceCode);
     
     // 2. Compiler en sections structurées
     const compiled = compile(ast);
   
     // 3. Enrichir avec les calculs culinaires (rendements, % du boulanger, ajustement des proportions)
     const analyzed = analyze(compiled, myDatabase);
   
     return analyzed.result;
   }
   ```
   
   :::tip[Raccourci Node uniquement]
   Si vous tournez exclusivement côté serveur sous Node.js (via un CLI ou un backend Next.js), le *package* `@gram-lang/cli` exporte un utilitaire `runPipeline(filePath, options?)`. Il orchestre les trois étapes ci-dessus et se charge même de la lecture du fichier à votre place :
   
   ```typescript
   import { runPipeline, GramCLIError } from '@gram-lang/cli';
   
   try {
     const { compiled, analyzed } = await runPipeline('recette.gram', { db: myDatabase });
     return analyzed ? analyzed.result : compiled;
   } catch (err) {
     if (err instanceof GramCLIError) {
       console.error(err.message); // ex : "File not found: recette.gram"
     }
     throw err;
   }
   ```
   
   Si vous omettez `db`, l'étape d'analyse est totalement ignorée (`analyzed` vaudra `null`). Jetez un œil à la [référence de l'API de `@gram-lang/cli`](/fr/docs/reference/api/#raccourci-optionnel-node-uniquement-gram-langcli) pour découvrir la liste exhaustive des options (ajustement des proportions, % du boulanger, etc.).
   :::
   
   :::note
   Voir la [Référence API](/fr/docs/reference/api/) pour la signature complète de `getAST`, `compile`, et `analyze`, ainsi que tout ce que le pipeline expose (ajustement des proportions, diff, avertissements, i18n).
   :::

2. ### Comprendre la Structure du JSON
   
   L'objet JSON retourné encapsule toute la recette de manière structurée. C'est votre matière première pour bâtir votre UI.
   
   Voici les champs les plus importants dans l'objet racine :
   - `title` *(string)* : Le nom de la recette (issu du `# Titre`).
   - `meta` *(object)* : Paires clé-valeur pour les métadonnées (ex : `author`, `yield`).
   - `shopping_list` *(array)* : Une liste agrégée de tous les ingrédients de toutes les sections.
   - `sections` *(array)* : Les instructions elles-mêmes, découpées par section de recette.
   - `metrics` *(object)* : `preparationTime` et `activeTime` en minutes, plus la masse et la nutrition quand la recette est passée par l'analyzer.
   - `miseEnPlace` *(array)* : Ce que coûte la préparation de chaque section, une entrée par section qui a une préparation.
   - `tasks` *(object)* : Tout ce qu'il y a à faire, avec sa durée et ce que chaque tâche attend. Tous les plannings se posent à partir de lui.
   - `schedule` *(object)* : Le planning par défaut posé à partir de `tasks`, avec un `totalTime`, un `idleTime`, une liste de `blocks` et ses `sessions` (une par journée de travail).
   - `generator` *(string)* : La version du compilateur qui a écrit ce JSON.
   
   Ignorez les champs inconnus et les valeurs de `kind` de bloc que vous ne connaissez pas : votre interface continuera de fonctionner quand une version mineure en ajoutera.
   
   #### À l'intérieur d'une Section
   
   Chaque `section` dans le tableau `sections` possède ses propres `ingredients`, `cookware` (matériel), et `steps` (étapes).
   
   ```json
   {
     "title": "Pâte",
     "ingredients": [ ... ],
     "cookware": [ ... ],
     "steps": [
       {
         "type": "step",
         "action": "Mélanger",
         "content": [
           "La ",
           {
             "id": "farine",
             "_usageId": "1",
             "qty": 500,
             "unit": "g",
             "normalizedMass": 500
           },
           " et l'",
           {
             "id": "eau",
             "_usageId": "2",
             "qty": 350,
             "unit": "ml"
           },
           "."
         ]
       }
     ]
   }
   ```
   
   Une étape ne porte plus son propre début et sa propre fin. Sa place dans le temps dépend du moment où se fait la mise en place, elle vit donc dans `schedule` (voir « Dessiner la chronologie » plus bas).

3. ### Logique de Rendu
   
   Puisque le JSON de Gram est hautement prévisible, générer l'UI n'est souvent qu'une affaire de simples boucles ou de `.map()` dans votre *framework* front-end.
   
   #### Exemple : Rendu des Étapes en React
   
   Voici une implémentation théorique illustrant comment itérer sur le tableau `steps` avec React :
   
   ```tsx
   function RecipeStep({ step }) {
     // Si c'est un simple nœud de commentaire
     if (step.type === 'comment') {
       return <p className="text-gray-500 italic">{step.value}</p>;
     }
   
     // Si c'est une étape d'instruction standard
     if (step.type === 'step') {
       return (
         <li>
           {step.action && <strong>[{step.action}] </strong>}
           {step.content.map((token, i) => (
             <StepToken key={i} token={token} />
           ))}
         </li>
       );
     }
   }
   
   // Un composant polymorphe pour afficher les tokens en ligne
   function StepToken({ token, cookwareRegistry }) {
     // 1. Les chaînes de caractères (strings) sont du simple texte brut
     if (typeof token === 'string') {
       return <span>{token}</span>;
     }
   
     // 2. Les Ingrédients et le Matériel sont des objets optimisés sans champ 'type', mais avec un 'id'.
     // On déduit le type en vérifiant si l'ID existe dans notre registre de matériel.
     if (!token.type && token.id) {
       const isCookware = !!cookwareRegistry[token.id];
       
       if (isCookware) {
         return <span className="text-blue-600 font-bold">{token.id}</span>;
       } else {
         return <span className="text-green-600 font-bold">{token.id} ({token.qty}{token.unit})</span>;
       }
     }
   
     // 3. Les autres tokens (minuteurs, températures) ont des champs 'type' explicites
     switch (token.type) {
       case 'timer':
         return <span className="bg-yellow-100 px-1 rounded">{token.quantity?.value}{token.unit}</span>;
       case 'temperature':
         // l'unité est déjà normalisée en °C/°F — pas de ° supplémentaire à ajouter ici
         return <span className="text-red-600">{token.quantity?.value}{token.unit}</span>;
       default:
         return null;
     }
   }
   ```
   
   En mappant intelligemment la propriété `type` sur vos propres composants, vous gardez un **contrôle total** sur le design, l'interactivité et l'accessibilité de votre application !

4. ### Dessiner la chronologie
   
   <Since v="1.4.0" />
   
   Pour dessiner un diagramme de Gantt ou un planning, lisez les blocs d'un planning. `recipe.schedule` est celui par défaut ; tout autre sort des mêmes `tasks` avec `layout()`, sans recompiler. Tous les temps sont en minutes depuis `0` et incluent déjà la préparation :
   
   ```typescript
   import { layout } from '@gram-lang/scheduler'; // ou scheduleFor() de '@gram-lang/kitchen'

   // miseEnPlace : 'perSection' (la préparation de chaque section juste avant elle, par défaut),
   //   'upfront' (toute la préparation au début) ou 'perSession' (la préparation de chaque
   //   journée de travail au début de cette journée).
   // rests : la durée d'un repos écrit en fourchette : 'shortest' (par défaut), 'balanced', 'longest'.
   const { schedule } = layout(recipe.tasks, { miseEnPlace: modeChoisi, rests: reposChoisis });
   // Pour le choix par défaut, recipe.schedule est la même chose, déjà calculée.
   
   for (const block of schedule.blocks) {
     if (block.kind === 'prep') {
       // La mise en place d'une section. `miseEnPlace` dit de quoi elle est faite.
       const prep = recipe.miseEnPlace.find((m) => m.section === block.section);
       draw('Mise en place', block.start, block.end, prep?.items);
     } else {
       // 'step' ou 'passive' : `block.step` est l'indice dans `sections[block.section].steps`,
       // commentaires compris.
       const step = recipe.sections[block.section].steps[block.step];
       const label = block.kind === 'passive' ? (block.track ?? 'Minuteur') : step.action;
       draw(label, block.start, block.end);
     }
   }
   ```
   
   Laissez votre lecteur choisir : le temps total et le temps d'attente diffèrent d'un choix à l'autre (`schedule.totalTime`, `schedule.idleTime`), pas `schedule.preparationTime`. Le moteur de rendu Gram, le playground, l'extension VS Code et la CLI offrent tous ce choix.
   
   Pour dessiner sur le calendrier plutôt, avec de vrais jours et de vraies heures et des repos étirés pour que le cuisinier évite la nuit, donnez les mêmes `tasks` à `project()` avec une heure de service, un fuseau horaire et des disponibilités. Chaque bloc du plan porte `start` et `end` en instants (UTC) et `startLocal` et `endLocal` en heure du cadran du fuseau. Voir [Planifier un repas](/fr/docs/how-to/plan-a-meal/) et la [référence du scheduler](/fr/docs/reference/api/scheduler/).
   
   :::caution[Champs dépréciés]
   Du code plus ancien peut lire `step.timings`, `step.backgroundTasks` ou `metrics.totalTime`. Ils fonctionnent encore et seront retirés en 2.0.0 : lisez plutôt `schedule`. Voir [Fonctionnalités dépréciées](/fr/docs/how-to/deprecations) et la [référence de l'API Kitchen](/fr/docs/reference/api/kitchen).
   :::
</Steps>
