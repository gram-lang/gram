title: "Créer une interface (UI) personnalisée à partir du JSON"
description: "Consommez le JSON compilé par Gram directement dans React, Vue ou Svelte pour concevoir votre propre interface."
---

Si vous développez une application web moderne (avec React, Vue, Svelte ou Next.js, par exemple), vous avez tout intérêt à consommer directement les données **JSON** compilées par Gram et à les relier à vos propres composants d'interface utilisateur (UI).

Bien que le parseur produise initialement un Arbre Syntaxique Abstrait (AST) brut, les packages `@gram-lang/kitchen` et `@gram-lang/analyzer` le transforment en un objet JSON hautement structuré et prêt à l'affichage. Ce guide vous montre comment extraire ces données programmatiquement et comment exploiter leur architecture en toute simplicité.

1. ### Récupérer le JSON
   
   Gram est conçu pour s'exécuter dans n'importe quel environnement (Node.js, runtimes Edge ou directement dans le navigateur). Pour obtenir la représentation JSON complète et enrichie d'une recette, combinez ses trois packages fondamentaux :
   
   ```typescript
   import { getAST } from '@gram-lang/parser';
   import { compile } from '@gram-lang/kitchen';
   import { analyze } from '@gram-lang/analyzer';
   
   function getRecipeData(sourceCode: string) {
     // 1. Parser le texte en arbre syntaxique abstrait
     const ast = getAST(sourceCode);
     
     // 2. Compiler en sections structurées et calculer l'ordonnancement par défaut
     const compiled = compile(ast);
   
     // 3. Enrichir avec les calculs culinaires (masses physiques, rendements, nutrition)
     const analyzed = analyze(compiled, myDatabase);
   
     return analyzed.result;
   }
   ```
   
   :::tip[Raccourci pour environnement Node.js]
   Si vous travaillez exclusivement côté serveur sous Node.js (via une CLI ou une route d'API Next.js), le package `@gram-lang/cli` exporte l'utilitaire `runPipeline(filePath, options?)`. Il orchestre l'ensemble du pipeline et prend en charge la lecture du fichier :
   
   ```typescript
   import { runPipeline, GramCLIError } from '@gram-lang/cli';
   
   try {
     const { compiled, analyzed } = await runPipeline('recette.gram', { db: myDatabase });
     return analyzed ? analyzed.result : compiled;
   } catch (err) {
     if (err instanceof GramCLIError) {
       console.error(err.message); // ex. : "File not found: recette.gram"
     }
     throw err;
   }
   ```
   
   Si vous omettez `db`, l'étape d'analyse physique est ignorée (`analyzed` vaut `null`). Consultez la [référence de l'API de `@gram-lang/cli`](/fr/docs/reference/api/#raccourci-optionnel-node-uniquement-gram-langcli) pour découvrir la liste des options (ajustement des proportions, pourcentages du boulanger, etc.).
   :::
   
   :::note
   Consultez la [Référence API](/fr/docs/reference/api/) pour la signature détaillée de `getAST`, `compile`, et `analyze`, ainsi que l'ensemble des fonctionnalités exposées (mise à l'échelle, diff sémantique, diagnostics d'avertissement, i18n).
   :::

2. ### Comprendre la structure du JSON
   
   L'objet JSON retourné encapsule l'intégralité de la recette sous une forme déterministe. Il constitue le socle complet de votre interface :
   
   - `title` *(string)* : Le nom de la recette (défini par l'en-tête `# Titre`).
   - `meta` *(object)* : Paires clé-valeur de métadonnées (ex. : `author`, `portions`, `yield`).
   - `shopping_list` *(array)* : La liste agrégée de tous les ingrédients de la recette, prête pour l'approvisionnement.
   - `sections` *(array)* : Les instructions culinaires découpées par section autonome.
   - `metrics` *(object)* : Métriques globales (`preparationTime`, `activeTime` en minutes, ainsi que la masse et la nutrition après analyse).
   - `miseEnPlace` *(array)* : Détail opérationnel et durées de préparation pour chaque section requérant une mise en place.
   - `tasks` *(object)* : Le graphe de tâches complet avec durées et dépendances, servant de base de calcul à tous les ordonnancements.
   - `schedule` *(object)* : L'ordonnancement théorique calculé à partir de `tasks`, comprenant `totalTime`, `idleTime`, les blocs ordonnancés (`blocks`) et le découpage par journée de travail (`sessions`).
   - `generator` *(string)* : La version du compilateur ayant généré le document.
   
   Pour garantir la compatibilité ascendante de votre interface lors des mises à jour mineures, ignorez gracieusement les propriétés non reconnues ou les nouvelles variantes de `kind` de blocs.
   
   #### Au cœur d'une section
   
   Chaque entrée du tableau `sections` regroupe ses propres listes d'ingrédients (`ingredients`), de matériel (`cookware`) et d'étapes (`steps`).
   
   ```json
   {
     "title": "Pâte",
     "ingredients": [ ... ],
     "cookware": [ ... ],
     "steps": [
       {
         "type": "step",
         "action": "Mélanger",
         "content": [
           "La ",
           {
             "id": "farine",
             "_usageId": "1",
             "qty": 500,
             "unit": "g",
             "normalizedMass": 500
           },
           " et l'",
           {
             "id": "eau",
             "_usageId": "2",
             "qty": 350,
             "unit": "ml"
           },
           "."
         ]
       }
     ]
   }
   ```
   
   Une étape ne porte plus de créneau temporel intrinsèque. Son calage dépend de la stratégie de mise en place retenue : les créneaux réels sont donc portés par l'objet `schedule` (voir « Dessiner la chronologie » ci-dessous).

3. ### Logique de rendu
   
   Puisque la structure du JSON de Gram est hautement régulière, la génération de votre vue consiste simplement à itérer sur les tableaux d'éléments via les méthodes standard de votre framework front-end.
   
   #### Exemple : rendu des étapes en React
   
   Voici une implémentation illustrant le rendu récursif du tableau `steps` et de ses jetons inline avec React :
   
   ```tsx
   function RecipeStep({ step }) {
     // Si c'est un nœud de commentaire
     if (step.type === 'comment') {
       return <p className="text-gray-500 italic">{step.value}</p>;
     }
   
     // Si c'est une étape d'instruction standard
     if (step.type === 'step') {
       return (
         <li>
           {step.action && <strong>[{step.action}] </strong>}
           {step.content.map((token, i) => (
             <StepToken key={i} token={token} />
           ))}
         </li>
       );
     }
   }
   
   // Un composant polymorphe pour afficher les jetons inline
   function StepToken({ token, cookwareRegistry }) {
     // 1. Les chaînes de caractères représentent du texte brut
     if (typeof token === 'string') {
       return <span>{token}</span>;
     }
   
     // 2. Les Ingrédients et le Matériel sont des objets optimisés sans champ 'type', identifiés par leur 'id'.
     // On distingue le matériel en vérifiant si l'identifiant figure dans notre registre de matériel.
     if (!token.type && token.id) {
       const isCookware = !!cookwareRegistry[token.id];
       
       if (isCookware) {
         return <span className="text-blue-600 font-bold">{token.id}</span>;
       } else {
         return <span className="text-green-600 font-bold">{token.id} ({token.qty}{token.unit})</span>;
       }
     }
   
     // 3. Les autres jetons (minuteurs, températures) portent un discriminant 'type' explicite
     switch (token.type) {
       case 'timer':
         return <span className="bg-yellow-100 px-1 rounded">{token.quantity?.value}{token.unit}</span>;
       case 'temperature':
         // L'unité est déjà normalisée en °C/°F
         return <span className="text-red-600">{token.quantity?.value}{token.unit}</span>;
       default:
         return null;
     }
   }
   ```
   
   En reliant chaque discriminant `type` à vos propres composants, vous conservez un **contrôle total** sur le design system, l'interactivité et l'accessibilité de votre interface.

4. ### Dessiner la chronologie
   
   <Since v="1.4.0" />
   
   Pour construire un diagramme de Gantt ou une chronologie d'exécution, exploitez les blocs temporels d'un ordonnancement. La propriété `recipe.schedule` fournit le planning standard ; toute autre variante se calcule directement à partir du graphe `recipe.tasks` via la fonction `layout()`, sans avoir à recompiler la recette. Toutes les durées sont exprimées en minutes relatives depuis `t = 0` et incluent le temps nécessaire à la mise en place :
   
   ```typescript
   import { layout } from '@gram-lang/scheduler'; // ou scheduleFor() depuis '@gram-lang/kitchen'

   // miseEnPlace : 'perSection' (préparation de chaque section immédiatement avant son exécution, par défaut),
   //   'upfront' (toute la préparation regroupée au démarrage) ou 'perSession' (préparation regroupée
   //   au début de chaque journée de travail).
   // rests : élasticité accordée aux minuteurs passifs déclarés sous forme de fourchette
   //   (ex. fermentation, repos, cuisson lente) : 'shortest' (par défaut), 'balanced' ou 'longest'.
   const { schedule } = layout(recipe.tasks, { miseEnPlace: modeChoisi, rests: elasticiteChoisie });
   // Pour la configuration par défaut, recipe.schedule contient déjà ce résultat calculé.
   
   for (const block of schedule.blocks) {
     if (block.kind === 'prep') {
       // Mise en place d'une section : recipe.miseEnPlace détaille les opérations associées
       const prep = recipe.miseEnPlace.find((m) => m.section === block.section);
       draw('Mise en place', block.start, block.end, prep?.items);
     } else {
       // 'step' (action active) ou 'passive' (minuteur passif) :
       // block.step correspond à l'index de l'étape dans sections[block.section].steps
       const step = recipe.sections[block.section].steps[block.step];
       const label = block.kind === 'passive' ? (block.track ?? 'Minuteur passif') : step.action;
       draw(label, block.start, block.end);
     }
   }
   ```
   
   Offrez à vos utilisateurs le choix de la stratégie : le temps total de réalisation et les périodes de battement varient selon le mode retenu (`schedule.totalTime`, `schedule.idleTime`), tandis que le temps de préparation active reste invariant (`schedule.preparationTime`). Le moteur de rendu de Gram, le Playground, l'extension VS Code et la CLI intègrent tous ce sélecteur de stratégie.
   
   Pour projeter la production sur un calendrier réel (avec dates réelles, heures horloge murale, et adaptation des temps passifs pour respecter les plages de repos nocturnes), transmettez ces mêmes `tasks` à la fonction `project()` avec une heure de service cible, un fuseau horaire et les plages de disponibilité de la brigade. Chaque bloc du plan fournit `start` et `end` sous forme d'instants absolus (UTC) ainsi que `startLocal` et `endLocal` en heure locale du fuseau cible. Pour plus de détails, consultez le guide [Planifier un repas](/fr/docs/how-to/plan-a-meal/) et la [référence de l'API du scheduler](/fr/docs/reference/api/scheduler/).
   
   :::caution[Champs dépréciés]
   Les applications antérieures à la version 1.4.0 lisaient parfois `step.timings`, `step.backgroundTasks` ou `metrics.totalTime`. Bien que maintenus pour assurer la rétrocompatibilité jusqu'à la version 2.0.0, ces champs sont obsolètes : consommez désormais la structure `schedule`. Pour en savoir plus, consultez la page [Fonctionnalités dépréciées](/fr/docs/how-to/deprecations) et la [référence de l'API Kitchen](/fr/docs/reference/api/kitchen).
   :::
