Vous voulez servir un pain de campagne dimanche à 13 h. La pâte demande une pousse de nuit, vous ne cuisinez qu'entre 8 h et 22 h, et vous préféreriez ne pas pétrir à 4 h du matin. Ce guide vous mène de la recette à une fiche avec une heure pour chaque tâche, puis à votre agenda.

<Steps>

1. ### Écrire le repos en fourchette

   Un repos exact (`~_{8h}`) ne bougera jamais. Un repos écrit en fourchette peut bouger, et c'est cette marge que Gram utilise pour que votre travail évite la nuit :

   ```gram
   ---
   title: Pain de campagne
   ---

   ## Pâte ->&pâte

   [Pétrir] Mélanger la @farine{500g} avec l'@eau{350ml} et le @sel{10g}, puis pétrir ~{20min}.

   [Pousse] Laisser pousser ~_{8-16h}.

   ## Cuisson

   [Cuire] Façonner la &pâte{850g} et cuire à ^{230C} pendant ~{30min}.
   ```

   `~_{8-16h}` dit « prête dès 8 heures, encore bonne à 16 ». Voir [Durées exactes et fourchettes](/fr/docs/reference/syntax/times/#durées-exactes-et-fourchettes).

2. ### Dire quand on sert et quand on peut cuisiner

   ```bash
   gram plan pain.gram --serve "2026-10-11 13:00" --tz Europe/Paris --available 08:00-22:00
   ```

   `--serve` est une date et une heure locales, `--tz` le fuseau dans lequel on les lit, et `--available` quand vous pouvez travailler, tous les jours. Sans `--available`, Gram suppose que vous pouvez cuisiner à toute heure.

   Si vous cuisinez toujours au même endroit, réglez le fuseau une fois plutôt que de répéter `--tz` : `gram config set timezone Europe/Paris` (dans `.gram/config.yaml`, ou dans votre configuration globale pour tous les projets). Sans l'un ni l'autre, Gram prend le fuseau de votre machine, qui est le mauvais sur un serveur ou quand vous planifiez pour une autre ville.

3. ### Lire la fiche

   ```text
   Fiche de production — Pain de campagne
   Servi le dimanche 11 octobre à 13:00

   samedi 10 octobre · J-1
     vers 21:35        Mise en place — Pâte (3m)
                       Ingrédients (base) (3 × 1m)
     vers 21:40        Pâte — Pétrir (20m)
                       Mélanger la farine (500 g) avec l'eau (350 ml) et le sel (10 g), puis pétrir ⏲️ 20 min.
     vers 22:00        Pousse — Pâte (14h 30m, jusqu'à vers dim. 12:30)
                       Laisser pousser ⏳ 8-16 h (passive).
                       ! Repos allongé de 8h à 14h 30m pour éviter vos heures d'indisponibilité

   dimanche 11 octobre · Jour J
     vers 12:30        Mise en place — Cuisson (1m)
                       Ingrédients (base) (1 × 1m)
     vers 12:30        Cuisson — Cuire (30m)
                       Façonner la pâte (850 g) et cuire à 🔥230 °C pendant ⏲️ 30 min.

   À régler
     - Le travail de Jour J tombe le samedi 10 octobre au lieu du dimanche 11 octobre.
   ```

   Sans aucune contrainte, la pousse de 8 heures aurait placé le pétrissage à 4 h 10 le dimanche. Gram a allongé la pousse à 14 h 30 pour que le pétrissage se termine à 22 h le samedi, et le dit sur le repos lui-même. Les heures sont arrondies à cinq minutes (« vers ») : votre four n'est pas un chronomètre.

   La ligne « À régler » est un rappel, pas un échec : le travail de la recette tombe le samedi alors qu'elle n'a jamais dit être une recette sur deux jours. Pour une pousse de nuit, c'est exactement ce que vous voulez, et vous pouvez l'ignorer. Si vous préférez le dire à Gram, ancrez la première section (`## Pâte ~{-1d}`) : le samedi devient le jour J-1 et la remarque disparaît. Une ancre est cependant une échéance : la pâte doit être prête samedi à la même heure que le service, la pousse n'est donc plus allongée. Voir [Jours et heures](/fr/docs/reference/syntax/times/#jours-et-heures).

4. ### Changer ce que vous ne pouvez pas faire

   Les disponibilités peuvent différer selon le jour de la semaine et la date, et vous pouvez répéter `--available` :

   ```bash
   gram plan pain.gram --serve "2026-10-11 13:00" \
     --available 08:00-22:00 \
     --available sat=09:00-23:00 \
     --available 2026-10-09=none
   ```

   `sat=…` est un jour de la semaine (`mon` … `sun`), `2026-10-09=none` une date où vous n'êtes pas du tout disponible. Plusieurs plages vont après une même clé (`sat=08:00-09:00,18:00-22:00`). Si une limite ne peut pas être respectée, la fiche le dit après les jours (par exemple quand le repos est exact, ou une fourchette trop étroite pour servir), et ce que vous pouvez y faire. Voir [diagnostics et contraintes non résolues](/fr/docs/explanation/planning-in-real-time/#diagnostics-et-contraintes-non-résolues).

5. ### Obtenir un agenda

   ```bash
   gram plan pain.gram --serve "2026-10-11 13:00" --available 08:00-22:00 --ics pain.ics
   ```

   Le fichier contient un événement par tâche, et une alarme 5 minutes avant chaque tâche qui demande vos mains. Les événements sont en UTC : n'importe quelle application d'agenda les affiche dans son propre fuseau. Importez-le, ou ouvrez-le avec votre agenda.

6. ### Lire la recette avec ses heures

   La fiche suit l'ordre du temps ; la recette suit l'ordre de ses sections. Pour lire la recette elle-même avec le moment de chaque étape, donnez les mêmes options aux commandes qui l'affichent :

   ```bash
   gram view pain.gram --serve "2026-10-11 13:00" --available 08:00-22:00
   gram export pain.gram --format md --serve "2026-10-11 13:00" --available 08:00-22:00
   ```

   La recette porte alors une heure à côté de chaque étape, le jour quand il change, les repos avec la note de celui qui a été allongé, et en tête quand on sert et ce qui n'a pas pu être arrangé. Ajoutez `--with-sheet` à `gram export` ou `gram print` pour avoir la fiche après la recette, les deux dans un seul document. Dans le playground, l'aperçu et la vue Markdown le font dès qu'une heure de service est réglée dans « Plan ».

7. ### Choisir un autre format

   `--format md` pour du Markdown (à coller dans vos notes), `--format html` pour un fragment, `--format json` pour le plan et la fiche sous forme de données. La fiche est dans la langue de votre projet (`language` dans `.gram/config.yaml`).

</Steps>

## Dans le playground

Choisissez le diagramme de Gantt ou la vue « Fiche de production », ouvrez « Plan », et indiquez quand on sert, votre fuseau et votre plage de disponibilité. Le diagramme de Gantt se lit alors en vrais jours et heures, grise les heures où vous n'êtes pas disponible et entoure les repos qui ont été allongés.

## Depuis du code

```typescript
import { compile } from '@gram-lang/kitchen';
import { project, runSheet } from '@gram-lang/scheduler';
import { runSheetToText } from '@gram-lang/renderer';

const compiled = compile(ast);
const plan = project([{ graph: compiled.tasks, title: compiled.title ?? undefined }], {
  serveAt: '2026-10-11T13:00',
  timeZone: 'Europe/Paris',
  availability: { daily: [{ start: '08:00', end: '22:00' }] },
});

console.log(runSheetToText(runSheet(plan), compiled, { lang: 'fr' }));
```

Voir la [référence du scheduler](/fr/docs/reference/api/scheduler/) et [Planifier en heures réelles](/fr/docs/explanation/planning-in-real-time/).
