## It compiles!

With the syntax becoming stable, the focus is shifting towards the **compiler**. Instead of just parsing text, Gram now uses the structured data to provide concrete help: nutritional estimation, automatic mass conversions, and smart timings.

## Welcome to Codeberg

First and foremost, **Gram has moved to Codeberg**. This migration aligns with the values of open-source, ethical hosting, and community-driven development that drive this project.

## Release highlights

### Mass unification

To help with calculations, the system now converts ingredient quantities into grams (hence the project's name):

* **Converts volumes** (`cups`, `ml`, …) to `grams` using average densities.
* Distinguishes between **net mass** (what you eat) and **purchasing mass** (what you buy), accounting for waste such as banana peels or egg shells.
* Supports **custom densities** in recipe frontmatter when defaults are not accurate enough.
* **Initial ingredient database**: An internal proof-of-concept database powers these calculations.

### Nutritional calculation

The compiler can now estimate the nutritional value of a recipe from the ingredient database:

* Estimates calories, protein, carbs, sugar, fat, fiber, and salt.
* Define `portions: 4` in metadata to get per-serving metrics.

### Time estimation

The Playground now calculates and displays three distinct time metrics:

* **Active time**: Actual hands-on work time (stirring, chopping, cooking).
* **Total time**: From start to finish, accounting for parallel background tasks.
* **Prep time (est.)**: An automated estimation of the mise en place based on ingredients and preparations.

## There's more

### Playground

* Updated preview mode with new icons and a cleaner design.
* New panel showing the nutritional breakdown with an estimate badge when available.
* New toggle to show or hide calculated masses alongside the original text quantities.

### Documentation overhaul

Restructured documentation into Syntax, Compiler Features, and Technical sections, with diagrams explaining logic like mass conversion.

### Fixes

* Comments and notes in the Playground (Markdown and preview) are now visually distinct and no longer shift step numbering.
* Fixed percentage calculations inside alternative groups (`@A{}|@B{10% @A}`).
* Improved parser robustness and detection of ingredient modifiers and inline preparation notes.
